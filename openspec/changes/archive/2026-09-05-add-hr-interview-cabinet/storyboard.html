UX Critic checklist
  • Empty, filtered-empty, loading and load error differ.
  • Stale refresh never looks freshly loaded.
  • Archived future records cannot appear upcoming or open live.
  • Read-only detail omits private notes and inferred results.
  • Applied export scope and Moscow date basis are legible.

Transition and state audit

? verify in implementation

Focus and announcements

  • Does modal focus return to the exact row/room trigger?
  • Do copy, refresh and download messages announce without stealing focus?
  • Are field errors connected to their labels and blocking error focused?

Authorization changes

  • Does role loss close and clear the manager modal immediately?
  • Does a terminal 410 perform one persisted check, freeze controls and stop reconnect?
  • Does account switching clear prior HR cache and navigation?

Data truth

  • Are missing values always `Не указано`, without participant-name fallback?
  • Is `Предстоящее` limited to active, unfinished, future-scheduled rooms?
  • Does failed refresh label retained rows as stale?

Export recovery

  • Does the client distinguish JSON errors from workbook bytes?
  • Do 413 and 429 messages guide a manual retry without automatic generation?
  • Does zero-result export still download and announce zero interviews?

Scope is mock-complete

All new HR surfaces have a live mock. Existing landing, candidate admission, editor, step switching and language selection remain governed by their current interfaces. Their only integration question is absence or placement of the new manager trigger, which is specified above.

Questions resolved by contract

  • Entry: profile/navigation and server-confirmed manager room header.
  • Shape: cabinet section plus two dialogs.
  • Cancel: retain no server change; pending requests prevent close.
  • Destructive behavior: none added; archived history is read-only.
