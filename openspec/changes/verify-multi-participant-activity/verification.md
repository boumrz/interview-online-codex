## Обнаруженный дефект P1

Все кандидаты сохраняют свои 300 введённых символов локально, но видят лишь часть ввода других участников. В финальном прогоне три менеджера имеют по 665 символов (653 введённых цифры вместо 2 100); семь кандидатов имеют разные документы длиной 733–961 символ. Ранее диагностический запуск воспроизвёл ту же форму расхождения: [RED с деталями каждого редактора](/Users/romanzheltov/Desktop/frontentd-projects/interview-online-codex/output/playwright/multi-activity/1788689867384/report.json).

Read-only разбор очереди выявил потерю Yjs-дельт: heartbeat каждые 2,5 секунды использует dedupe для типа yjs_update, при этом очередь может удалить непустые дельты и отменить уже отправляемую дельту. Потерянный промежуточный CRDT update мешает применить последующие зависимые изменения. Дополнительные пути потери — очистка дельт при recovery и вытеснение старого сообщения при превышении 300 элементов очереди. Удаление при лимите в этом сценарии отдельно не доказано.

Область следующего исправления: сохранять непустые дельты при heartbeat/recovery/переполнении очереди, не ослабляя серверные проверки свежести снимка и контекста шага; предусмотреть детерминированный тест задержанного POST с heartbeat, reconnect с неподтверждёнными изменениями, затем повторить текущий RED и проверки медленной сети/устаревших снимков. Перед production-изменениями требуется обновлённый валидированный OpenSpec scope.
