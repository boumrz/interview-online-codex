# METRICS.3 — Языки опубликованных шагов интервью

На дашборде «Использование интервью» владелец счётчика видит, сколько интервью и сколько шагов приходятся на каждый язык и сколько интервью включало несколько языков.

## Требования

- R-01. Наблюдение возникает при показе подключённому кандидату опубликованного шага действующей комнаты. Первый показ каждого языка в комнате даёт одно достижение для комнаты. Первый показ языка на каждом отдельном шаге даёт одно достижение для шага. При смене публичного языка на том же шаге учитывается каждый показанный язык. Наблюдение не требует правки кода.
- R-02. Шаг определяется постоянным идентификатором задачи. Повторный показ после переключения, изменение порядкового номера, обновление страницы, переподключение и одновременные показы разным кандидатам сохраняют однократность. Шаги, которые остались в библиотеке или в подготовке интервьюера, пустая комната и просмотр завершённого интервью исключены.
- R-03. Группы соответствуют языку редактора: JavaScript/TypeScript (Node.js), Python, Kotlin, Java, SQL и «Без языка» (plaintext). Когда в одной комнате впервые показан второй отличный язык программирования, достигается отдельная цель многоязычного интервью. «Без языка» участвует в распределении комнат и шагов и исключается из порога многоязычности.
- R-04. Сервер проверяет актуальный доступ, роль кандидата, публичный шаг и язык. В базе сохраняются только внутренние ключи комнаты и шага, язык и момент первого наблюдения. При удалении комнаты удаляются наблюдения. Удаление задачи сохраняет факт её показа. Метрика получает только разрешённую цель с языковой категорией или цель многоязычности.
- R-05. В дашборде считаются достижения целей за выбранный период. Измерение начинается после выкладки сбора. У старых комнат сохранены текущие настройки задач, но последовательность их фактического показа и переключения языков неизвестна. Блокировка счётчика или потеря подтверждения уже зафиксированного показа может уменьшить число достижений в Яндексе.

## API и приёмка

После показа публичного шага клиент передаёт `sessionId`, `eventToken`, `taskId` и канонический `language` в `POST /api/realtime/rooms/{inviteCode}/language-observations`. Сервер возвращает `language`, `firstForRoom`, `firstForStep`, `firstMultilanguageRoom`. Значение `true` разрешает одному клиенту отправить соответствующую цель. Повтор подтверждается с тремя `false`. Устаревшее наблюдение получает HTTP 204. Недействительные данные подключения приводят к отказу в доступе.

В счётчике `109032539` дашборд «Использование интервью» использует следующие цели.

| Цель | Идентификатор события | ID цели | Показатель |
| --- | --- | --- | --- |
| P04 | `int_room_language_v1` | 681498142 | Интервью по языкам |
| P05 | `int_step_language_v1` | 681498323 | Шаги интервью по языкам |
| P06 | `int_multilanguage_room_v1` | 681498409 | Многоязычные интервью |

В P04 и P05 каждый виджет считает события своей цели (`ym:ep:eventsNumber`) в отчёте параметров событий (`event_params`). Единственная группировка `ym:ep:eventParamsLevel2` даёт значения параметра `language`. Фильтр применяется к событиям конкретной цели, поэтому два языка в одном визите остаются отдельными строками.

| ID | Требования | Ожидаемый результат |
| --- | --- | --- |
| AC-01 | R-01, R-02 | Два кандидата одновременно открыли один шаг Python. Появилось по одному достижению для интервью и шага. Второй шаг Python добавил одно достижение только для шага. |
| AC-02 | R-01, R-03 | После Python появился шаг без языка, затем на нём был опубликован SQL. В отчёте видны все три категории, многоязычное интервью учтено один раз при появлении SQL. |
| AC-03 | R-02, R-04 | Запоздавший запрос с прежним шагом, роль интервьюера, неверный токен и открытие завершённой комнаты не создают фактов. Удаление комнаты очищает её факты в БД. |
| AC-04 | R-04, R-05 | Достижения передаются единичными общими категориями, без идентификаторов, URL, текста кода, заданий и данных участников. По прошлому периоду результаты этой новой серии не восстанавливаются. |

14 ноября 2026 года [интеграционный сценарий](../../backend/src/test/kotlin/com/interviewonline/controller/InterviewLanguageObservationIntegrationTest.kt) прошёл через HTTP-контроллеры с реальным Spring-контекстом и H2. До реализации проверка получила HTTP 404. Отдельно на H2 в режиме PostgreSQL применена [миграция V42](../../backend/src/main/resources/db/migration/V42__room_task_language_observations.sql) и подтверждено каскадное удаление. Независимая проверка серверного кода завершена. Тот же сценарий автоматически входит в Maven/Surefire под именем `InterviewLanguageObservationPostgresTest`; целевой вызов из `backend` — `mvn -Dtest=InterviewLanguageObservationPostgresTest test`. Тест поднимает собственную схему в тестовой базе PostgreSQL и применяет миграции Flyway. В окружении проверки JDBC-подключение остановила ошибка `Operation not permitted`. Выкладка и проверка по реальным достижениям ожидаются.
