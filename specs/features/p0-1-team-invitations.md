# P0.1 — приглашения и вступление в команду

Статус: реализована; прежние проверки указаны ниже. Актуализировано: 2026-10-02.
Результат: команда использует одну постоянную действующую ссылку; принявший
приглашение становится участником и видит доступные ему разделы.

## Требования

- **R-01. Одна ссылка:** у команды не более одного действующего приглашения.
  Повторный выпуск вращает token того же invitation ID и немедленно делает
  прежний token недействительным. Перевыпуск только вручную; revoke очищает
  текущую ссылку. Новую автоматическую ротацию/expiry не вводить.
- **R-02. Многоразовое вступление:** разные пользователи принимают одну ссылку;
  принятие не расходует её. Повторное вступление после выхода допустимо по
  действующей ссылке. Членство/права после rejoin — [P3.1](p3-1-membership-lifecycle.md).
- **R-03. Управление:** выпуск/reissue/revoke работают с актуальным invitation ID.
  После выпуска, перевыпуска и reload/revalidation действующая ссылка автоматически
  видна для копирования, без отдельного «Показать ссылку». Pending invitation
  восстанавливается после потерянного ответа без повторного автоматического выпуска.
- **R-04. Секрет:** поле/clipboard содержат полный URL текущего сайта. Raw URL/token
  остаются только в памяти интерфейса и разрешённом получении секрета; не попадают
  в recovery state, обычные API-ответы или логи. Reload восстанавливает приглашение
  по безопасным данным, затем получает допустимую действующую ссылку.
- **R-05. Гонки:** выпуск, принятие и перевыпуск сериализуются по команде. Старый
  token отклоняется также в гонке с принятием; повтор не создаёт лишнее приглашение.
- **R-06. Состав:** OWNER/ADMIN видят нового участника без ручного refresh;
  вступивший видит состав по своим правам. Текущий раздел — единые
  [настройки команды](p0-4-team-settings-audit.md), прежний `/members` перенаправляется.
- **R-07. Интерфейс:** copy/revoke кнопки по содержимому, поле ссылки по доступной
  ширине. Экран принятия не показывает техническое пояснение о скрытии protected
  данных. Native AX automation и внешняя email-доставка не входят в эту фичу.

## Приёмка и проверка

| ID | Требования | Сценарий → результат | Проверка |
| --- | --- | --- | --- |
| AC-01 | R-01–R-02, R-06 | Два пользователя принимают один URL → ACTIVE состав обновлён, ссылка действующая | Invitation integration + E2E |
| AC-02 | R-01, R-03–R-05 | Потерянный ответ/reload/copy → та же ссылка без секрета в recovery; reissue/revoke → старый token отказан | Recovery/idempotency/concurrency integration + E2E |
| AC-03 | R-02 | Участник выходит и принимает действующую ссылку → права P3.1, без старых explicit grants | Lifecycle integration |
| AC-04 | R-04, R-07 | Поле/clipboard → полный текущий URL; обычные ответы/log/recovery без token | Security/browser verification |

Прежние E2E и lifecycle результаты — [историческая редакция](../references/history/p0-1-team-invitations-before-2026-10-02.md),
общая проверка — [бизнес-evidence 28.09](../references/business-logic-verification-2026-09-28.md).
