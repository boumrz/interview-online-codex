### P0.1 Приглашения и участники команды

Цель: приглашение работает как постоянная выпущенная ссылка, новый участник появляется в составе, а раздел «Участники» доступен вступившему пользователю.

Уже сделано:

- pending invitation восстанавливается после копирования/обновления без хранения raw URL/token;
- reissue/revoke работают по актуальному invitation ID;
- изолированный invitation E2E прошёл: вступление `8/8`, автоматический показ/перевыпуск и восстановление ссылки после потерянного ответа `2/2`;
- проверены typecheck, build, strict validation, diff check.

Итоговая проверка:

- targeted browser E2E подтвердил вступление по приглашению, обновление состава и доступ вступившего пользователя к разделу «Участники»;
- проверены восстановление pending-ссылки без сохранения секрета в recovery state, автоматический показ, ручное перевыпускание и отзыв;
- native AX automation вынесена в отдельную инфраструктурную задачу и не входит в эту фичу.

Acceptance:

- OWNER/ADMIN видят нового участника после принятия приглашения без ручного refresh данных;
- вступивший пользователь видит состав команды по своим правам;
- после копирования и reload/revalidation ссылка не исчезает из управления;
- перевыпуск возможен только вручную;
- revoke очищает текущую ссылку.

## Корректировка по продуктовой проверке 2026-09-23

- У команды может быть только одна действующая ссылка. Повторный выпуск вращает токен того же приглашения и немедленно делает предыдущий токен недействительным.
- Одну действующую ссылку могут принять несколько разных пользователей; принятие не расходует ссылку. Повторное вступление после выхода допустимо по действующей ссылке.
- Экран управления показывает одну ссылку, а поле и буфер обмена содержат полный URL текущего сайта. Секрет не сохраняется в recovery state и не попадает в обычные ответы API или логи.
- Выпуск, принятие и перевыпуск сериализуются по команде; старый токен отклоняется и при гонке с принятием.
- После выпуска, перевыпуска и повторной загрузки управление автоматически получает доступную действующую ссылку и показывает её для копирования без действия «Показать ссылку». URL остаётся только в памяти текущего интерфейса, не в recovery state.
- На экране принятия приглашения нет технического пояснения о скрытии защищённых данных.
- Действия «Отозвать приглашение» и «Копировать ссылку» имеют ширину по содержимому; поле ссылки может занимать доступную ширину.
