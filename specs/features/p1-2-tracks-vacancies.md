### P1.2 Треки и вакансии

Цель: в команде появляются реальные справочники «Треки» и «Вакансии», а не заглушка.

Готово:

- backend storage/API для активных треков и вакансий:
  - `GET /api/teams/{teamId}/tracks`;
  - `GET /api/teams/{teamId}/tracks?status=active|archived`;
  - `POST /api/teams/{teamId}/tracks`;
  - `POST /api/teams/{teamId}/tracks/{trackId}/vacancies`;
  - `PATCH /api/teams/{teamId}/tracks/{trackId}`;
  - `POST /api/teams/{teamId}/tracks/{trackId}/archive`;
  - `POST /api/teams/{teamId}/tracks/{trackId}/restore`;
  - `PATCH /api/teams/{teamId}/tracks/{trackId}/vacancies/{vacancyId}`;
  - `POST /api/teams/{teamId}/tracks/{trackId}/vacancies/{vacancyId}/archive`;
  - `POST /api/teams/{teamId}/tracks/{trackId}/vacancies/{vacancyId}/restore`;
- OWNER/ADMIN могут создавать треки и вакансии;
- OWNER/ADMIN могут редактировать, архивировать и восстанавливать треки/вакансии;
- MEMBER может читать справочник, но не создавать/редактировать/архивировать;
- чужая/недоступная команда скрывается как `TEAM_NOT_FOUND`;
- активные названия треков уникальны внутри команды, активные названия вакансий
  уникальны внутри трека;
- UI вкладки «Треки и вакансии» больше не показывает «Раздел готовится» и
  поддерживает создание, переименование, архив и восстановление трека/вакансии;
- UI имеет переключение «Активные» / «Архив»;
- UI поддерживает поиск по названию трека и вакансии;
- API и UI показывают счётчики active/archive только по данным доступной команды;
- архив родительского трека скрывает его из активного списка, восстановление возвращает;
- проверки:
  - backend `TeamTrackVacancyIntegrationTest` — зелёный;
  - frontend isolated E2E P1.2 — зелёный:
    - создание трека/вакансии;
    - rename/archive/restore трека и вакансии;
    - поиск по названию вакансии.

Что сделать:

- P1.2 MVP готов; дальнейшие доработки здесь считаются polish/интеграцией с P1.5
  (например, запрет выбора архивных треков/вакансий при создании интервью).

Acceptance:

- можно создать трек и вакансию;
- архив родителя корректно влияет на детей;
- чужая команда и архивные сущности не используются при создании интервью;
- интерфейс не раскрывает кандидатов/количество комнат без прав.

## Контекст существующего интервью

- **R-01.** В редакторе TEAM-интервью активный участник может добавить, сменить
  или очистить трек/вакансию. Новые связи допускаются только для активных сущностей
  этой команды; неизменённые исторические архивные связи сохраняются. Выбор другого
  трека сбрасывает старую вакансию. Сохранение атомарно с остальными сведениями и
  той же revision по [P1.5 R-14](p1-5-team-interview-creation.md), без замены задач
  и сохранённой программы интервью. В PERSONAL этих полей нет.
- **AC-01.** Интервью без контекста → выбрать трек и его вакансию → сохранить
  и заново открыть → выбор сохранён; смена трека сбрасывает вакансию, очистка
  убирает обе связи. 409/сеть сохраняют черновик; чужая/новая архивная связь
  отклоняется сервером без частичной записи.

Реализовано и технически проверено 05.10: 10 целевых PostgreSQL-сценариев
редактора и 7 production browser-сценариев `e2e-team-interview-edit.mjs` прошли.
Пользовательская приёмка ожидается; текущий независимый обзор и evidence —
в [общем отчёте](../references/2026-10-05-personal-hiring-and-team-interview-context.md).

## Уточнение 2026-09-23

- Создание трека и вакансии запускается заметными кнопками с плюсом и
  открывает диалог. Формы не занимают место в списке до нажатия кнопки.

## Корректировка интерфейса 2026-09-23

- Архивированная вакансия активного трека показывается в архиве отдельной записью с подписью родительского трека. Сам активный трек не выглядит архивированным и не получает действие восстановления.
- Архивированный трек остаётся самостоятельной записью архива; восстановление трека и вакансии доступны по их собственным действиям.
- Компактный поиск, вкладки и синие кнопки создания трека и вакансии находятся на одном уровне на широкой странице. При создании вакансии трек выбирается в диалоге.

## Визуальная корректировка 2026-09-24

- Карточки треков используют одну спокойную поверхность без вложенной рамки и толстой цветной боковой полосы у вакансии.
- Список треков в диалоге новой вакансии раскрывается над затемнением; Escape сначала закрывает список, затем диалог.

## Уточнение после проверки интерфейса 2026-09-23

- Трек показан родительской карточкой, его вакансии визуально вложены и подписаны. Пользовательские подписи для задач объясняют, что это задачи для интервью по треку или вакансии; внутреннее слово «программа» не используется в основном управлении.
- Пустой архив и пустой активный список занимают только высоту содержимого. Счётчики активных вакансий учитывают только вакансии активных треков.
- OWNER/ADMIN могут навсегда удалить вакансию и пустой трек после подтверждения. Сущности, связанные с интервью, а также трек с вакансиями сервер отклоняет с `409`.

## Доработка диалогов и управления задачами — 2026-09-24

- Диалоги создания трека и вакансии показывают один заголовок; диалог вакансии компактный, а поля занимают доступную ширину.
- До выбора трека в диалоге вакансии показана короткая подсказка, объясняющая следующий шаг.
- Счётчики под фильтрами читаются как акцентная вспомогательная информация.
- В архивных действиях оранжевый цвет одинаково заметен в обычном и наведённом состоянии.
- Управление программой задач сосредоточено в одном редакторе: сохранение выбранного состава сразу делает программу действующей. Отдельные кнопки публикации и архивации не показываются в карточках; архивную программу можно вернуть через её редактор.

## Иерархия треков и вакансий — 2026-09-27, 21:33

Активный трек — отдельная родительская карточка; его задачи отдельным блоком. Каждая вакансия — самостоятельная вложенная карточка с заголовком/действиями и собственной программой. Между карточками постоянный промежуток; поверхности/границы различимы в обеих темах, включая768px, без наложений. Настройка задач, переименование, архив/восстановление и удаление треков/вакансий сохраняются. Не смешивать отменённый архив библиотечных задач с архивами треков/вакансий.

## Фильтры интервью и кандидатов — 2026-09-28

- В командных списках интервью и кандидатов доступны фильтры по треку и вакансии. Фильтры сочетаются с поиском/«Мои интервью» либо периодом кандидатов.
- Выбор нового трека сбрасывает прежнюю вакансию. Возврат к «Все треки»/«Все вакансии» снимает соответствующее ограничение; фильтры не сохраняют данные кандидатов в recovery state.
- Фильтрация применяется сервером к списку и пагинации. Excel кандидатов получает те же фильтры команды, трека, вакансии и периода. При смене фильтра незавершённая выгрузка отменяется.
- Архивные треки и вакансии доступны для поиска исторических интервью. Ошибка загрузки справочника допускает повторную попытку.

Проверка интерфейса 2026-09-28: `e2e-team-workspace-business.mjs` — 8/8 на изолированном frontend5185 с API fixtures; перед реализацией первые шесть сценариев дали RED 6/6. Подтверждены доступ MEMBER без флага нанимающего, общие настройки, действия интервью без назначения, серверные фильтры/Excel, внешний UUID, архивный справочник и отмена устаревшей выгрузки. Frontend typecheck PASS. Серверные права проверяются отдельно backend integration tests.
