## Ошибки и восстановление списка

- **R-01. Обновление после мутации:** ошибка сохранения сохраняет введённый
  черновик. После успешного повторного сохранения библиотека показывает
  подтверждённое сервером содержание и revision. Запоздавший ответ загрузки,
  начатой до сохранения, не оставляет старые данные на экране; после его
  завершения получается актуальный список. Результат сохраняется после reload.
  То же правило обновления применяется к созданию, импорту и удалению задачи.
  Права, CAS, текущие фильтры и разделение аккаунтов сохраняются.

| ID | Требование | Проверяемая последовательность | Проверка |
| --- | --- | --- | --- |
| AC-01 | R-01 | Ошибка сохранения → загрузка старой revision удерживается → повторный PATCH подтверждает новую revision → старый GET завершается → новый GET и UI показывают подтверждённый текст; reload сохраняет результат | Поведенческая E2E с настоящим API и управляемым порядком ответов; исходный RED сохранён |

Проход полноты: актор — участник с действующим правом редактирования; ошибка,
повтор, старый ответ, видимый результат и reload определены. Изменений
серверных прав или хранения нет; блокирующих продуктовых вопросов нет.
Проверка исправления и ограничения — в [отчёте 04.10](../references/2026-10-04-full-project-verification.md).

## Приёмка действующей функциональности

- сотрудники команды могут читать доступные задачи;
- автор/админ редактирует по правам;
- неавтор без прав может сделать копию, но не перезаписать оригинал;
- правка и удаление библиотечного оригинала не меняют snapshot уже созданного интервью;
- удаление убирает текущие ссылки из наборов/программ атомарно, сохраняя порядок оставшихся задач;
- чужая задача и неактивное членство не дают доступа к изменению/удалению;
- прежние архивные записи возвращаются в библиотеку миграцией без потери содержания;
- archive/restore endpoints отсутствуют (`404`), legacy query `status` не фильтрует каталог;
- архивы треков и вакансий остаются самостоятельной функциональностью.

## Корректировка интерфейса 2026-09-23

- «Копировать» кладёт название, описание, язык и стартовый код задачи в буфер обмена для передачи другому человеку. Список задач и база данных не меняются; действие дублирования в интерфейсе не предлагается.
- Активная вкладка сохраняет выбранное состояние и цвет текста при наведении (уточнение UI.2 от 2026-09-27). Поиск компактный и находится в строке вкладок на широкой странице.
- В пустом состоянии и карточках библиотеки нет двойных декоративных рамок.
- Кнопка создания расположена рядом с вкладками и имеет общий с другими действиями создания синий цвет.

## Передача задач между пользователями

- «Копировать» сохраняет переносимые данные задачи (название, язык, описание и стартовый код), без внутреннего ID. Данные можно отправить другому человеку и вставить в «Импортировать» личной или командной библиотеки.
- Импорт в команду по ID собственной личной задачи сохранён. Для обмена между аккаунтами используется копирование и вставка данных.
- Копирование доступной библиотечной задачи не зависит от архивного состояния: архивы задач отменены.
- Личная библиотека содержит действия «Копировать» у задачи и «Импортировать» рядом с созданием задачи.

## Актуальная политика удаления — 2026-09-27, 21:33

Отменяет прежний запрет удаления использованных задач и архивы задач. В каждой библиотеке PERSONAL/TEAM остаётся единый список без архивного фильтра; личные и командные данные не смешиваются. Архивирование/восстановление больше не являются доступной функциональностью или API. Существующие архивные записи возвращаются в список без потери данных. Изменение/копирование/импорт и текущие серверные права сохраняются.

Автор/OWNER/ADMIN (для PERSONAL — владелец) может удалить задачу, даже если она уже использована в наборе, программе или комнате. Удаление убирает библиотечную задачу и её текущие каталоговые ссылки; самостоятельные snapshots в уже созданных комнатах/интервью не теряют название, условие, код, язык, порядок, обязательность и оценки. Чужая задача и неактивное членство по-прежнему недоступны. Snapshot сохранён после reload и повторного realtime join. Не допускаются orphan FK, partial delete и зависимость чтения старой комнаты от наличия шаблона.

Актуальная проверка удаления и UI: [отчёт 21:33](../references/ui-2-period-room-edit-library-delete-verification-2026-09-27.md).
