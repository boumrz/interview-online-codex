## Ошибки и восстановление списка

- **R-01. Командные наборы:** создание, импорт, изменение и удаление обновляют
  список по подтверждённому сервером результату. Ошибка сохраняет черновик,
  повтор не теряет обновление при запоздавшем GET. Общий инвариант и пределы
  заданы в [P1.3 R-01](p1-3-team-task-library.md#ошибки-и-восстановление-списка);
  состав, порядок, CAS и серверные права набора сохраняются.

| ID | Требование | Проверяемая последовательность | Проверка |
| --- | --- | --- | --- |
| AC-01 | R-01 | Старый GET удерживается при повторном сохранении → сервер подтверждает новое название/revision → старый ответ завершается → актуальное название, состав и порядок видны в UI и после reload | E2E командного набора с управляемым порядком ответов |

Проход полноты: автор либо OWNER/ADMIN с активным членством; успех/ошибка,
повтор, старый ответ и reload определены. Права и snapshots не меняются.
Проверка исправления — в [отчёте 04.10](../references/2026-10-04-full-project-verification.md).

## Приёмка действующей функциональности

- набор можно выбрать, проверить и изменить его упорядоченный состав в селекторе задач без дублирующего списка;
- порядок воспроизводим;
- в каждой библиотеке один список без архивных фильтров, счётчиков и действий; PERSONAL/TEAM данные разделены;
- использованный набор разрешено удалить: его задачи остаются в существующих интервью, room.tasks не меняется;
- удаление набора не удаляет составляющие его библиотечные задачи;
- удаление библиотечной задачи изымает её текущую ссылку из состава набора, сохраняя порядок остальных задач;
- при удалении командного набора room.team_task_set_id становится null, историческая ревизия и snapshot сохраняются;
- прежние архивы мигрируют в общий список без потери IDs/items; конфликтующие названия получают различающий суффикс;
- archive/restore endpoints отсутствуют (`404`), legacy query `status` не фильтрует каталог;
- права владельца PERSONAL и автора/OWNER/ADMIN TEAM проверяются сервером;
- UI работает на tablet/short viewport.

- «Копировать» командный набор записывает его название и упорядоченный список задач в буфер обмена, не создавая дубликат в библиотеке.
- «Копировать» личный набор работает так же: текст для передачи человеку попадает в буфер обмена, новый набор не появляется.

- Личная библиотека называет эту сущность «набором» во вкладке, заголовке и диалогах; синяя кнопка создания стоит рядом с вкладками.

## Передача наборов между пользователями

- «Копировать» личный или командный набор сохраняет переносимые данные: имя, полное содержимое каждой задачи и их порядок. Внутренние ID не передаются.
- Получатель вставляет данные через «Импортировать» в личной или командной библиотеке. Импорт создаёт независимые задачи и набор в пространстве получателя. Импорт своего личного набора в команду по ID сохранён.
- Копирование доступных наборов не зависит от архивного состояния: архивы задач и наборов отменены. Если задача набора недоступна, копирование показывает понятную ошибку.
- Неверный или устаревший текст в поле импорта объясняет, что требуются данные из новой кнопки «Копировать».
- Пустое состояние личных наборов не обрезается скруглением контейнера.
