## Подготовка и создание

- **R-01. Подготовка:** модальное окно над списком не создаёт комнату до отправки.
  Разделы «Основное», «Задачи», «Участники»; длинные поля прокручиваются отдельно
  от действий. Отмена возвращает к списку, успешное создание открывает комнату.
  В «Основное» доступны название и необязательные имя кандидата, позиция и дата
  интервью в МСК. Имя/позиция обрезаются по краям, пустое значение хранится как
  `null`, предел — 200 Unicode code points; дата хранится как UTC instant.
  Имя/позиция остаются строками и для значений вроде `234`; отсутствие даты
  не препятствует созданию.
  Эти сведения сохраняются атомарно с комнатой, без отдельного второго запроса.
- **R-02. Материалы:** можно выбрать набор, отдельные активные задачи команды,
  дополнить набор или создать интервью без задач. Трек/вакансия/набор выбираются
  как необязательный контекст. Итоговые задачи представлены поисковым MultiSelect
  без дублирующих карточек; выбор источника отмечает задачи по умолчанию, состав
  можно изменить до создания. Ссылки на источники и версии сохраняются отдельно
  от итогового состава; выбранные задачи опубликованной программы обязательны
  в комнате по [P4.2](p4-2-mandatory-programme-interview.md).
- **R-03. Состав запроса:** явный упорядоченный `selectedTaskIds` означает только
  перечисленные активные задачи. Если поле отсутствует, совместимый запрос
  включает программную основу, полный выбранный набор и отдельные `taskIds`. Без набора `taskSetId`
  и `taskSetRevision` равны `null`; taskless-комната имеет `nodejs` и пустой редактор.
- **R-04. Участники:** создатель автоматически становится владельцем комнаты и
  виден среди интервьюеров; самого себя в форме не выбирает. Другие интервьюеры
  выбираются из активной команды поисковым MultiSelect. Кандидата в форме не
  назначают. Внешний нанимающий выбирается по точному нику с асинхронным подтверждением
  найденного человека по P2.3, без глобального каталога. Ошибки назначений не
  создают частичную комнату; назначение одного человека в несовместимые роли
  отклоняется. Назначения входят в тело идемпотентного запроса.
  TEAM-селектор явно подписан «Внешний нанимающий (необязательно)»; ACTIVE
  коллега уже имеет общий доступ и не получает отдельное hiring назначение.
- **R-05. Повтор и атомарность:** `POST /api/teams/{teamId}/interviews` требует
  `Idempotency-Key`. То же тело и ключ возвращают ту же комнату; иной body с
  прежним ключом даёт `IDEMPOTENCY_KEY_REUSED`. Невалидный/чужой/архивный источник
  либо неактивный сотрудник отклоняется сервером без частичных данных.
  Нормализованные сведения кандидата входят в сравнение тела. Повтор формы после
  сетевой ошибки с тем же телом использует прежний ключ только в памяти; изменение
  тела создаёт новый ключ. Черновики кандидата и ключи не записываются в UI storage.
  Текущий ответ 401 скрывает форму и удаляет приватный черновик/ключ из памяти;
  запоздалый отказ прежнего аккаунта не сбрасывает новый вход. Ошибка выбора
  материала или внешнего назначения остаётся исправимой в открытой форме.
- **R-06. Снимки:** задачи копируются в snapshot — сохранённую версию материалов
  интервью. Правка/удаление источника не меняет интервью; ревизия набора фиксируется;
  programmeId/programmeVersion проверяются до создания по P4.2. Подробнее — owning спеки материалов.

## Права и публичная ссылка

| Состояние человека/комнаты | Вход и возможности |
| --- | --- |
| ACTIVE участник команды, корректно созданное TEAM-интервью | Общая роль interviewer без отдельного назначения и личного HR-флага: вход, сведения кандидата, результат, переименование и управление интервью |
| Текущий владелец комнаты при действующем членстве | Роль owner; ownership команды остаётся отдельным контрактом |
| Внешний явно назначенный interviewer/нанимающий | Только назначенный доступ по P2.3; без членства и чужих кандидатов |
| Гость, чужой аккаунт, LEFT/REMOVED либо устаревший owner/interviewer credential | Вход по действующей публичной ссылке как candidate; старая роль не возвращает управление. Явное гостевое назначение в текущем пространстве — по P2.3 R-09 |
| Существующая finished/frozen комната | Публичный вход сохраняется; записи и просмотр регулируются P3.3 |
| Archived или несуществующая комната | Без публичного admission; архивирование не восстанавливается ссылкой |

- **R-07. Общие права:** ACTIVE membership — источник общего TEAM authority;
  индивидуальное room assignment не является обязательным условием для коллег.
  Переименование и обычное удаление интервью с подтверждением доступны активным
  участникам; сервер применяет те же права. Отдельные orphan lifecycle операции
  имеют собственные ограничения P3.2, которые это правило не расширяет.
- **R-08. Публичный admission:** ссылка допускает кандидата без авторизации,
  с чужим аккаунтом и после выхода/удаления. Legacy tokens не дают TEAM-права и
  не мешают войти кандидатом. Кандидат не получает внутренний чат, личные заметки,
  сведения кандидата или manager-команды.
- **R-09. Перенесённые комнаты:** кандидатский вход распространяется и на старые
  PERSONAL→TEAM комнаты. Это не превращает их в canonical team-created интервью
  и не открывает управление метаданными, TEAM HR-проекции или private данные.
  Сохраняется постоянный признак происхождения корректно созданных TEAM-комнат.
- **R-10. Смена прав и гонки:** управляющая команда проверяет членство после
  ожидания блокировок в порядке команда → комната. Отзыв/смена scope инвалидируют
  старые SSE/event credentials и отложенные записи. Delayed callback чата не
  восстанавливает роль; старые PERSONAL Yjs/persistence/idempotent chat и
  получатели внутреннего чата не пересекают TEAM scope. Новое подключение по
  ссылке продолжает работать кандидатом. Секретные legacy room tokens не
  возвращаются в обычных TEAM ответах.

## Список, фильтры и управление

- **R-11. Список:** одна лента доступных интервью команды; отдельный повторный
  блок «Мои процессы» не показывается. Карточка содержит название, материалы,
  контекст трека/вакансии, интервьюеров и результат. Основное действие — «Войти
  в комнату», копирование кандидатской ссылки вторично; UUID не заменяет название.
- **R-12. Фильтры:** `GET /api/teams/{teamId}/interviews` сочетает поиск `q`,
  принадлежность и независимые optional `trackId`/`vacancyId`. Выбор обоих —
  пересечение; фильтрация до пагинации. «Мои интервью» выключен по умолчанию и
  означает автора создания, а не текущего владельца; автор не меняется при transfer.
  Архивные треки/вакансии доступны для исторических интервью по P1.2.
- **R-13. Кабинет кандидатов:** все ACTIVE участники имеют одинаковые права
  списка, деталей и Excel. Экспорт использует те же серверные фильтры/набор;
  смена контекста отменяет устаревший запрос по [P3.4](p3-4-hiring-export.md).
- **R-14. Редактирование/удаление:** одна явная кнопка «Редактировать» заменяет
  карандаш названия и действие «Сведения» на TEAM-карточке. Диалог редактирует
  название, имя кандидата, позицию, дату МСК, трек, вакансию, выбранных командных
  интервьюеров и существующие разрешённые внешние
  назначения по P2.3 без входа в realtime-комнату. `GET /api/teams/{teamId}/interviews/{interviewId}/details`
  читает название, контекст и metadata revision одним снимком; `PATCH` этого пути сохраняет
  полный снимок атомарно при совпадении revision. Трек и вакансию можно добавить,
  изменить или убрать; при смене трека прежняя вакансия сбрасывается. Новые связи
  допускают только активные сущности той же команды. Неизменённый исторический
  архивный контекст сохраняется. Optional `context: {trackId, vacancyId}` в PATCH
  задаёт обе связи, явные `null` очищают их, отсутствие `context` сохраняет их для
  совместимых клиентов. Пустое название/невалидные
  сведения отклоняются, устаревшая revision даёт 409 без частичной записи.
  Сетевая ошибка или 409 сохраняет черновик; явная загрузка актуальных сведений
  заменяет его. Ответ 401/403/404 скрывает приватные поля и блокирует сохранение.
  Смена аккаунта/команды закрывает старые данные и ограждает поздние ответы.
  Ссылка, автор, задачи и сохранённая программа интервью сохраняются; смена контекста
  не заменяет материалы и их snapshots. Раздел «Участники» совпадает с созданием:
  другие интервьюеры выбираются из ACTIVE коллег, внешний нанимающий — по нику.
  Текущий владелец не снимается и не выбирается как другой интервьюер.
  Список выбранных интервьюеров является черновиком до «Сохранить», применяется
  атомарно с остальными сведениями и использует ту же revision. Отмена, сеть или
  конфликт не создают частичного изменения состава. Изменение выбранного состава
  не сужает общий доступ ACTIVE коллег и не снимает отдельные внешние/гостевые
  назначения по P2.3. Новые выбранные коллеги должны оставаться ACTIVE при записи;
  устаревшие участники не получают восстановление роли. Optional `interviewerIds`
  задаёт полный выбранный состав, отсутствие сохраняет его для совместимых
  клиентов, `[]` снимает выбор обычных ACTIVE интервьюеров. GET возвращает
  `ownerUserId` и `interviewerIds` без включения owner/нанимающих/кандидатов/
  внешних или неактивных назначений. Новые цели проверяются после team→room
  locks; невалидный состав даёт `TEAM_MEMBER_NOT_FOUND` без частичной записи.
  Эта ошибка выбора сохраняет черновик и допускает исправление; отказ доступа
  к самой комнате по-прежнему очищает приватную форму. Справочник участников
  читается по всем страницам, без потери выбранного человека за пределами
  первых 100; UI показывает имена, а не ID. Внешние роли
  добавляются/снимаются отдельными подтверждёнными действиями внутри диалога.
  Legacy title-only `PATCH /api/teams/{teamId}/interviews/{interviewId}`
  остаётся совместимым. Сведения не раскрываются в публичном room payload. Удаление
  требует подтверждения, удаляет связанные данные/назначения и закрывает live
  соединение после транзакции.

## Технические инварианты комнаты

- **R-15. Realtime:** REST admission, stream-status/SSE и POST relay согласованы
  с текущей ролью; manager-команды не зависят от legacy owner token. Приватная
  подготовка следующей задачи доступна управляющим, недоступна кандидату до
  публикации. Устаревшая `revision` не перезаписывает новую подготовку.
- **R-16. Сохранение:** подготовка хранит code/language/briefing/focusMode и Yjs
  snapshot/sequence; публикация переносит подготовленные материалы в открытый
  шаг. Подтверждённый редакторный snapshot публикуемой задачи сохраняется durable
  в комнате/задаче и восстанавливается после reload. Эти инварианты сохраняются
  при сбое и отзыве прав; статусы frozen/finished регулируются P3.3.
