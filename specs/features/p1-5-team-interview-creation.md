### P1.5 Создание командного интервью

Цель: организатор может создать командное интервью с задачами или без них, при необходимости указать трек/вакансию и назначить других интервьюеров. Кандидат присоединяется по ссылке.

Уже сделано:

- экран подготовки командного интервью показывает безопасную форму без создания
  комнаты;
- в форме можно выбрать активный трек или вариант «без трека»;
- после выбора трека можно выбрать активную вакансию или вариант «без вакансии»;
- выбранный трек/вакансия отображаются как явный контекст будущего интервью;
- backend walking skeleton создания командного интервью:
  - `POST /api/teams/{teamId}/interviews`;
  - обязательный `Idempotency-Key`;
  - активный участник команды может создать комнату из активного командного
    набора, отдельных задач или без задач;
  - опционально сохраняются активный трек и активная вакансия;
  - в `rooms` сохраняются `team_id`, `origin_team_id`, `team_track_id`,
    `team_vacancy_id`, `team_task_set_id`, `team_task_set_revision`;
  - повтор того же запроса с тем же ключом возвращает ту же комнату без
    дубля;
  - повтор ключа с другим телом возвращает `IDEMPOTENCY_KEY_REUSED`;
  - TEAM-комната изолирована от legacy token-доступа;
- UI формы подготовки создаёт командное интервью из выбранных задач,
  трека/вакансии, отправляет idempotency key и показывает карточку созданного
  интервью без перехода в legacy-room;
- backend принимает назначения сотрудников по ролям `interviewerIds` и
  `candidateIds`, включает их в idempotency hash и отклоняет повтор ключа с
  другим набором назначений;
- backend проверяет, что назначаемые сотрудники являются активными участниками
  той же команды, один пользователь не выбран сразу в две роли, а ошибка
  назначения не создаёт частичную комнату;
- назначения сохраняются в `room_participants` как роли `interviewer` и
  `candidate`;
- DTO создания и списка командных интервью возвращают `assignees`;
- backend список командных интервью:
  - `GET /api/teams/{teamId}/interviews`;
  - активный участник видит только комнаты своей команды;
  - чужие TEAM-комнаты не попадают в ответ;
  - поддержан поиск `q` по названию интервью, треку, вакансии и задачам;
  - список не раскрывает legacy invite-код до этапа grants/admission;
- раздел «Интервью» команды показывает реальные карточки созданных командных
  интервью вместо placeholder: ID, количество задач, трек, вакансию, ревизию
  набора, порядок задач и назначения по ролям;
- UI формы подготовки загружает участников команды и позволяет выбрать
  других интервьюеров; создатель назначается владельцем автоматически;
- карточка созданного интервью и карточка в списке показывают интервьюеров
  и дают скопировать ссылку для кандидата;
- server-side вход в TEAM-комнату по `GET /api/rooms/{inviteCode}` открыт
  назначенным активным сотрудникам команды и кандидатам по ссылке:
  - назначенный `interviewer` получает роль `interviewer`, может управлять
    комнатой, но не получает права выдавать grant;
  - назначенный `candidate` получает роль `candidate` без управляющих действий
    и без списка access members;
  - внешний держатель ссылки получает роль `candidate` без прав управления;
  - неназначенный активный участник команды, legacy owner/interviewer token и
    удалённый/stale участник получают безопасный `404`;
  - legacy room tokens не возвращаются в ответах TEAM-комнат;
- realtime admission для TEAM-комнаты использует тот же серверный контракт:
  - `stream-status` и SSE `stream` открываются назначенным сотрудникам и
    внешним кандидатам по ссылке;
  - state sync выдаёт роль `interviewer`/`candidate` и eventToken без legacy
    room tokens;
  - `yjs_update` relay принимается от подключённого назначенного участника;
  - неназначенные участники команды, legacy owner/interviewer token и stale
    eventToken после удаления участника получают безопасный `404`;
  - роль при event relay пересчитывается через активный team membership и
    `room_participants`, а не через legacy `ownerUser`;
- список командных интервью возвращает `inviteCode`, а карточка интервью
  показывает кнопку «Открыть комнату» назначенному владельцу или интервьюеру
  и кнопку копирования ссылки для кандидата; неназначенный участник видит
  обзорную карточку без ложного CTA;
- manager-only workspace для задач TEAM-комнаты работает через серверные
  room-команды без legacy owner-token:
  - назначенный `interviewer` может читать и сохранять непубличную workspace
    следующей задачи;
  - `revision` защищает от stale overwrite;
  - сохраняются `code`, `language`, `briefingMarkdown`, `focusMode`,
    `yjsDocumentBase64` и `yjsSequence`;
  - назначенный `candidate` получает `403`;
  - удалённый/stale interviewer получает безопасный `404`;
  - публикация подготовленной задачи через `next-step` переносит подготовленные
    code/language/briefing в открытую комнату;
- realtime editor snapshot для опубликованной задачи TEAM-комнаты сохраняется
  durable в `rooms.code`, `room_tasks.solution_code`,
  `room_tasks.workspace_yjs_document_base64` и
  `room_tasks.workspace_yjs_sequence`; старый сценарий delayed PERSONAL save →
  TEAM scope transition остаётся закрытым и не мутирует комнату;
- назначенный `interviewer` может управлять TEAM-комнатой без legacy
  owner-token через проверенные realtime/REST команды:
  - `set_step` переключает опубликованную задачу;
  - `notes_update` сохраняет общие заметки интервьюера;
  - `task_rating_update` сохраняет оценку задачи;
  - `POST /api/rooms/{inviteCode}/verdict` завершает комнату с verdict;
  - назначенный `candidate` получает `403` на manager-only команды;
- создатель TEAM-интервью автоматически получает роль владельца комнаты даже
  без собственного ID в списке интервьюеров; он может открыть комнату сразу
  после создания. Выход из команды или снятие доступа по-прежнему закрывает
  комнату серверной проверкой активного членства. В ответах назначения он
  отображается как `owner`;
- realtime manager workspace для TEAM-комнаты работает на backend:
  - назначенный `interviewer` открывает подготовку inactive task через
    `manager_workspace_open`;
  - `manager_workspace_briefing_update`,
    `manager_workspace_language_update`,
    `manager_workspace_focus_mode_update` и
    `manager_workspace_yjs_update` durable сохраняют черновик задачи;
  - назначенный `candidate` получает `403` и не видит приватный черновик;
  - публикация через `set_step` берёт подготовленный realtime snapshot;

Acceptance:

- после создания нет частичной комнаты;
- чужие/архивные треки, вакансии, задачи и сотрудники отклоняются сервером;
- выбранные интервьюеры видны сразу после создания и в списке интервью команды;
- кандидат может открыть интервью по скопированной ссылке без членства в команде;
- повтор запроса не создаёт дубликат;
- выбранная задача сохраняется как snapshot и не меняется после правки библиотеки.

## Корректировка продуктового сценария 2026-09-23, 13:45

- Создание интервью не требует набора задач: можно выбрать отдельные активные командные задачи, дополнить ими набор или создать интервью совсем без задач. Опубликованная программа выбранного трека/вакансии по-прежнему добавляет обязательную основу.
- Создатель автоматически назначается владельцем интервью и не выбирает самого себя в форме. Других сотрудников можно назначить интервьюерами.
- Кандидатов при создании не выбирают: ссылка комнаты позволяет кандидату присоединиться без членства в команде. Ссылка доступна для копирования после создания и в карточке интервью; держатель ссылки получает только роль кандидата. Ранее удалённый назначенный сотрудник не восстанавливает доступ через старую роль.
- Форма не использует вложенные декоративные карточки для назначений; кнопка называется «Создать интервью».
- Ответы и список возвращают `taskSetId` и `taskSetRevision` как `null`, если набор не выбирали. Пустая комната получает исходный язык `nodejs` и пустой редактор.
- Комната получает постоянный признак создания через командный сценарий. При обновлении схемы он восстанавливается для существующих интервью из набора и по источнику создания `team`. Просто переведённая в командный контекст личная комната не становится доступной по ссылке кандидата и не принимает отложенные личные изменения.
- Проверено локально: `TeamInterviewCreationIntegrationTest` 27/27, `TeamAccessIntegrationTest` 17/17, `RoomAccessServiceTest` 3/3, полный браузерный набор командного пространства 42/42. В существующей локальной базе восемь интервью без набора сохранили признак командного создания после миграции.
## Уточнение карточки интервью 2026-09-23

- Основное действие карточки — синяя кнопка «Войти в комнату»; копирование ссылки для кандидата является вторичным действием. Технический UUID не занимает место под названием интервью.
- Создатель интервью показывается среди назначенных интервьюеров, поскольку он уже владеет комнатой и может в неё войти. Пустой блок «Мои процессы» не занимает место, когда у пользователя нет назначенных процессов.
- OWNER/ADMIN видят отдельное действие безвозвратного удаления интервью с подтверждением. Сервер проверяет роль, удаляет связанные назначения и данные комнаты и закрывает активное соединение после завершения транзакции.

## Фильтр интервью 2026-09-23, 15:08

- На странице интервью команды одна лента карточек. Отдельный блок «Мои процессы» над лентой не показывается: он повторял карточки.
- Переключатель Ant Design «Мои интервью» по умолчанию выключен и показывает все доступные командные интервью. Во включённом состоянии список ограничен интервью, созданными текущим пользователем; поиск работает вместе с фильтром. Выключение снова показывает все интервью.
- Автор создания сохраняется отдельно от текущего владельца комнаты и не изменяется при передаче владения. Для уже созданных интервью происхождение восстанавливается при обновлении схемы настолько точно, насколько позволяют существующие данные.

## Переименование командной комнаты 2026-09-23

- У названия интервью в командном списке есть карандаш для переименования. Он доступен текущему владельцу комнаты и OWNER/ADMIN команды; остальные участники не видят это действие.
- Название меняется в той же карточке с явными действиями «Сохранить название» и «Отмена». Пустое название не принимается; сервер применяет те же ограничения, что при создании интервью.
- `PATCH /api/teams/{teamId}/interviews/{interviewId}` принимает `{"title":"..."}`, повторно проверяет активное членство и права на сервере, сохраняет новое название без изменения ссылки, автора и назначения интервьюеров. Новое название видно в списке и после обновления страницы.
