### P2.1 Layout режимы комнаты

Цель: комната корректно работает в режимах Focus / Work / Overview.

Текущее решение (2026-09-23): видимых режимов Focus/Work/Overview нет; раскладка выбирается автоматически по ширине, а кнопка «Только markdown» меняет основной редактор у интервьюера и кандидата. Ниже сохранены технические результаты предыдущей итерации, в том числе проверки внутренней адаптивной раскладки.

Уже сделано:

- переключатели Focus / Work / Overview и auto-mode по фактической геометрии
  рабочей области уже реализованы в `RoomContextPanels`;
- вкладка «Редактор» не возвращена: редактор остаётся прямым region;
- в Focus вспомогательные области снова доступны через aux-tabs без editor-tab,
  а возврат в редактор сделан отдельным действием «К редактору»;
- локальные splitters работают клавиатурой/мышью и не отправляют room
  mutations/split/resize события;
- кандидат не видит manager surfaces, личные заметки и publish action;
- editor/Yjs session не remount-ится при 20 reflow/panel transitions, сохраняет
  code, selection, vertical/horizontal scroll, drafts, chat read position и
  room session id без synthetic form mutations;
- временное отсутствие scroll overflow не стирает выбранную пользователем
  позицию редактора; при возвращении узкой панели она восстанавливается;
- в Focus с открытым редактором ни одна скрытая вспомогательная вкладка не
  помечается как выбранная;
- поздняя загрузка профиля не очищает уже введённый черновик личной заметки.
- проверка:
  - unit `roomContextPanelLayout.test.ts` — зелёный `3/3`;
  - frontend isolated E2E:
    `candidate receives no manager surfaces`,
    `focus mode keeps auxiliary surfaces reachable`,
    `remediation: editor is a direct Focus region...` — зелёный `3/3`;
  - совместный frontend E2E прогон Focus, 20 переходов, desktop/tablet zoom и
    usable geometry — зелёный `4/4`;
  - полный E2E набор поверх изолированной PostgreSQL схемы с включённой
    диагностикой SSE — зелёный `19/19`;
  - frontend `npm run typecheck` — зелёный.

Итоговая проверка:

- полная матрица desktop/tablet и zoom 100/125/150/200% прошла на чистом PostgreSQL runtime;
- тест корректно завершает старое посещение комнаты перед повторным входом, чтобы сервер освободил SSE-сессию;
- минимальная ширина редактора в режиме Work увеличена до 480 px внутри редактора; при нехватке полезной ширины интерфейс выбирает Focus;
- unit проверки границ splitter `3/3` прошли после изменения.

Acceptance:

- кандидат не видит внутренние панели и не может публиковать шаг;
- интервьюер может локально выбирать шаг без публикации кандидату;
- публикация шага — отдельное явное действие;
- draft/selection/scroll сохраняются при 20 переключениях/resize.

## Корректировка по продуктовой проверке 2026-09-23

- Видимые переключатели «Фокус» и «Обзор» удалены. Рабочая область адаптируется к размеру окна автоматически; на узкой области вспомогательные вкладки остаются доступными и есть возврат к редактору.
- Переключатель «Только markdown / Вернуть код» расположен на видном месте в верхней панели комнаты. Он меняет основной сценарий редактора для интервьюера и кандидата, а не только боковую панель условия.
- На неопубликованном шаге markdown заменяет основной кодовый редактор локального рабочего пространства; после публикации то же состояние применимо у кандидата.
- Действие называется «Заменить код на Markdown» / «Вернуть редактор кода» и
  визуально выделено. Возврат к списку интервью находится отдельно в шапке,
  называется «Вернуться к списку интервью» и ведёт в пространство текущего
  командного или личного интервью.
- В панели статусов не показываются штатное «Соединение: установлено» и локальный выбор шага. При разрыве связи остаётся предупреждение о восстановлении соединения; опубликованный шаг и состояние кандидата остаются видимыми.
