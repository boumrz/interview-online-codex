# P2.3 — назначения нанимающих и сведения кандидата

Статус: реализована по уточнению пользователя; PERSONAL назначения по нику, атомарное создание, текущие права и отзыв технически проверены на PostgreSQL 16 и в браузере. TEAM ограничения и гостевая HTTP-проекция сохраняются. Независимый security/reliability review — approve; пользовательская приёмка ожидается. Актуализировано: 2026-10-05.
Результат: управляющий приглашает нанимающего к конкретному PERSONAL или TEAM интервью
и назначает роль присутствующему гостю без расширения членства или раскрытия
других кандидатов.

## Границы и права

Общий ACTIVE TEAM доступ задаёт [P1.5](p1-5-team-interview-creation.md), отзыв
членства — [P3.1](p3-1-membership-lifecycle.md), состояния комнаты —
[P3.3](p3-3-interview-result.md). Нанимающий — пользователь с включённой личной
функцией hiring; явное назначение даёт ему room-role interviewer. Один профиль
hiring без назначения не даёт доступ к чужому интервью.

| Контекст | Правило назначения |
| --- | --- |
| ACTIVE коллега в TEAM | Общие права уже существуют; отдельный hiring grant и личный HR-флаг не нужны |
| Внешний человек для TEAM | Точный ник, enabled hiring и отсутствие ACTIVE членства в текущей команде |
| LEFT/REMOVED из этой команды | Разрешено новое внешнее назначение, строго новее изменения членства; старое назначение недостаточно |
| Исторический SUSPENDED | Внешнее hiring назначение запрещено; публичный candidate admission по P1.5 сохраняется |
| PERSONAL owner/interviewer, включая гостя | Поиск по точному нику, добавление и снятие зарегистрированного enabled нанимающего только для этой комнаты; без команды, треков, вакансий и слова «внешний» |
| Гость по публичной ссылке PERSONAL/TEAM | Входит кандидатом; хост может явно назначить interviewer и вернуть candidate в этой комнате, без аккаунта и team membership |

## Требования

- **R-01. Приглашение:** управляющий создаёт назначение атомарно при
  подготовке интервью или позже из комнаты. Повтор не создаёт дубль. Интерфейс
  использует асинхронный поиск по точному нику с подтверждением имени пользователя, без
  глобального каталога; в TEAM своих ACTIVE коллег не предлагают как внешних
  нанимающих, в PERSONAL членство в какой-либо команде не ограничивает подбор.
- **R-02. Проверка ника:** account preview без `teamId` доступен авторизованному
  автору PERSONAL интервью; с `teamId` требует ACTIVE автора этой команды. Ник обрезается по краям и сравнивается точно с учётом регистра,
  как при входе. Ответ содержит только имя и внутренний идентификатор для
  назначения; UI показывает имя. В TEAM активный коллега не предлагается как внешний
  нанимающий. Несуществующий/недоступный/disabled человек даёт одинаковый 404;
  список чужих аккаунтов не раскрывается. Legacy UUID API сохраняется для
  совместимости, интерфейс использует ник. Room-scoped preview
  определяет пространство по комнате и проверяет текущую authority; PERSONAL
  доступен по R-11, candidate/отозванный/сменивший scope credential не даёт
  manager preview. Авторизованный аккаунт использует собственные текущие
  роли, анонимный — только proof анонимного соединения; чужой eventToken не
  даёт авторизованному или анонимному аккаунту чужую account authority.
  Ответы не кешируются.
  Автопоиск после 300 мс ввода имеет предел ожидания 8 секунд; изменение ввода,
  смена контекста и закрытие отменяют старый запрос. Отказ/timeout освобождает
  submit; поздний ответ не заменяет текущий результат. Ошибка/отсутствие человека
  показываются по-русски, без требований ввести UUID.
- **R-03. Область:** выбранному нанимающему доступны только назначенные интервью/
  кандидаты в личном кабинете. Назначение не даёт team membership и доступ к
  остальным кандидатам. Явный внешний interviewer сохраняет назначенную роль
  согласно актуальной серверной проверке, не через устаревший owner token.
- **R-04. Отзыв:** снятие назначения убирает кандидата из его кабинета
  и снимает interviewer authority, сохраняя вход по ссылке как candidate.
  Не снимает защищённого owner. Изменение видно в двух вкладках и после reconnect;
  self-removal закрывает manager panel. Уход коллеги регулирует P3.1.
- **R-05. Гонки:** pending/failure/retry не создают дублей. Поздние ответы после
  demotion/смены контекста не возвращают роль и не переводят комнату в terminal
  ошибочно; актуальный `410` означает terminal. Первичный или свежий Room GET
  с `404`/`410` показывает нейтральное «Комната недоступна» до запроса имени,
  без редактора, бесконечной загрузки или повторного realtime admission.
  Архив и отсутствие комнаты не различаются в этом сообщении.
  Pending private данные очищаются
  и не появляются при повторном открытии. Отложенный callback чата не восстанавливает
  снятое назначение; authority перепроверяется после lock wait по P1.5.
- **R-06. Сведения из списка:** owner/interviewer PERSONAL и ACTIVE коллега
  TEAM открывают объединённый «Редактировать интервью» из карточки,
  по R-10/P1.5 R-14, без realtime join. Сохраняются metadata revision,
  имя кандидата/должность/МСК дата. Поиск по нику и снятие HR доступны
  в обоих пространствах по R-01/R-11; PERSONAL использует поле «Нанимающий»
  без повторяющего заголовка. TEAM раздел участников и выбор коллег — P1.5 R-14.
  Кандидату действие недоступно и на сервере.
- **R-07. Диалог:** конфликт/сетевая ошибка сохраняют черновик; смена аккаунта/
  команды отменяет запросы и закрывает старую форму. Изменения видны после
  закрытия/reload и в комнате. Название и сведения сохраняются атомарно:
  TEAM через общий редактор P1.5, PERSONAL по R-10. Нанимающие
  в PERSONAL и TEAM применяются отдельными успешными действиями добавления/снятия;
  закрытие общего редактора не отменяет уже подтверждённое назначение.
  Поисковый
  селектор ника и найденный результат для явного выбора по R-02 доступны при
  прокрутке, не перекрываются нижними действиями
  в обеих темах на 1366/768. Введённый ник и найденный результат сохраняются
  при потере фокуса, Escape и удалении другого назначенного нанимающего;
  явное удаление текста, успешный выбор и смена аккаунта/команды очищают
  соответствующий черновик. Закрытие и focus сохраняются по UI.2.
- **R-08. Изоляция:** назначение не создаёт HR tracking через candidate admission,
  не раскрывает чужие private notes и не открывает TEAM management в простой
  converted PERSONAL→TEAM комнате. Возвращение к допустимой interviewer роли
  восстанавливает только её разрешённые manager поверхности.
- **R-09. Гостевая роль:** хост назначает присутствующему гостю доступную роль
  interviewer/candidate сразу после публичного входа в PERSONAL или TEAM комнату.
  Отсутствие аккаунта не блокирует назначение. Явное назначение гостя действует
  только для этой комнаты и её текущего пространства; reconnect сохраняет
  действующее назначение через серверную reconnect capability, без раскрытия
  секрета в SSE или сохранённых данных. Отзыв немедленно закрывает private
  поверхности и записи, старый reconnect не возвращает роль сам. Хост может
  повторно явно назначить interviewer тому же присутствующему гостю. PERSONAL
  capability после переноса комнаты в TEAM не даёт управление: нужен новый
  candidate admission и новое явное назначение. Кандидат не назначает роли,
  owner через это действие не назначается; прежние expiry/restart ограничения
  reconnect capability сохраняются.

- **R-10. Личный редактор и проекция списка.** `/me/rooms` остаётся PERSONAL
  списком текущего аккаунта и возвращает компактные taskCount/упорядоченные
  task titles/finishedAt. Имена интервьюеров доступны только owner/interviewer;
  candidate не получает private metadata или внутренний каталог назначений.
  Открытие карточки не требует загрузки полного кода/заметок и realtime join.
  Авторизованные GET/PATCH `/me/rooms/{roomId}/details` возвращают/сохраняют
  title, candidateName, position, scheduledAt, revision; доступны только
  действующим PERSONAL owner/interviewer, не candidate/постороннему/архиву.
  Название меняет только owner, interviewer отправляет текущее название.
  Сохранение названия и metadata атомарно, revision/CAS проверяется после
  блокировки и повторной проверки прав; stale draft возвращает 409 без частичной
  записи. Старый owner title PATCH также обновляет revision при изменении.
  Старые metadata API и права сохраняются; HR API следуют R-11.
  Пустые сведения нормализуются
  в null, длины проверяются; legacy личные названия до 255 символов не усекаются.
  UI/роль/копирование/закрытие формы определены UI.2 R-30.

- **R-11. Нанимающие в личных интервью.** Авторизованный пользователь создаёт
  PERSONAL интервью с выбранными по точному нику зарегистрированными
  нанимающими; eligibility остаётся `isHr=true`. Несуществующий, обычный или
  отключивший функцию аккаунт получает одинаковый 404 без частичного создания.
  Перед записью комнаты сервер канонизирует и дедуплицирует targets, блокирует
  аккаунты в стабильном порядке и перепроверяет актуальный hiring-флаг. Явный
  null/неверный тип списка сохраняют 400 валидацию; отсутствующий/пустой список
  сохраняет обычное создание. Quick public создание не принимает назначения.
  PERSONAL manager preview/invite/remove работают по текущей owner/interviewer
  authority, включая действующий гостевой proof по R-09; candidate, чужой,
  отозванный или перенесённый credential не получает управление. Добавление
  выдаёт durable interviewer только выбранному аккаунту и одну hiring запись;
  повтор без дубля, явное повторное назначение после снятия восстанавливает роль.
  Снятие хранит candidate override и немедленно отзывает private/кабинетные
  права; owner защищён. Team membership не создаётся, треки/вакансии в PERSONAL
  не появляются. TEAM eligibility и свежесть membership остаются R-01–R-04.
  Авторизованный manager использует текущую собственную роль, не чужой
  guest/account eventToken; anonymous override допускает только актуальный
  анонимный proof. Все мутации перепроверяют scope, authority и применимую
  eligibility после row lock; lookup не выдаёт
  каталог и отвечает no-store. Автоматический tracking при публичном candidate
  входе и открытии комнаты отсутствует. Совместимый tracking допускается только
  текущему PERSONAL manager с enabled hiring, не повышает candidate и не
  восстанавливает снятый grant. Собственные интервью выбираются кабинетом по
  ownership; новые выбранные и исторические назначения — только по текущей
  authority. Уже выданные обычные гостевые роли/история сохраняются, данных и
  схемы не мигрируют.

- **R-12. Актуальная HTTP-проекция гостя.** GET `/rooms/{inviteCode}` принимает
  текущий `X-Room-Event-Token` присутствующего анонимного гостя и перепроверяет
  существующую server-attested reconnect/role proof: точная комната, текущее
  пространство, revision, expiry и отсутствие revoke. В PERSONAL действующий
  guest interviewer получает тот же Room DTO manager scope, который уже
  разрешён обычным RoomAccessService; новые роли не назначаются. В TEAM
  гостевая SSE interviewer роль даёт прежние realtime code/notes, но не
  authenticated HTTP metadata/HR/private Room DTO. Такой GET остаётся
  candidate-проекцией без teamId/accessMembers/notesMessages; scope нельзя
  угадывать по отсутствующему teamId. Авторизованный аккаунт использует свои
  текущие права и никогда не заимствует guest proof; proof аккаунтного
  соединения не авторизует анонимный GET. Обычные account/legacy owner GET
  сохраняют права и публичный код. GET с proof проверяет scope после room
  lock, ответ `private, no-store`; неверная/чужая/отозванная/перенесённая proof
  не возвращает manager поля. Токен остаётся в текущей памяти транспорта,
  без журналирования/сохранения в UI recovery state.
