# P2.3 — внешние назначения и сведения кандидата

Статус: реализована; объединённый TEAM-редактор технически проверен, пользовательская приёмка ожидается. Актуализировано: 2026-10-03.
Результат: управляющий приглашает внешнего нанимающего к конкретному интервью
и назначает роль присутствующему гостю без расширения членства или раскрытия
других кандидатов.

## Границы и права

Общий ACTIVE TEAM доступ задаёт [P1.5](p1-5-team-interview-creation.md), отзыв
членства — [P3.1](p3-1-membership-lifecycle.md), состояния комнаты —
[P3.3](p3-3-interview-result.md). Нанимающий — пользователь с включённой личной
функцией hiring; явное назначение даёт ему room-role interviewer. Один профиль
hiring без назначения не даёт доступ к чужому интервью.

| Контекст | Правило назначения |
| --- | --- |
| ACTIVE коллега в TEAM | Общие права уже существуют; отдельный hiring grant и личный HR-флаг не нужны |
| Внешний человек для TEAM | UUID, enabled hiring и отсутствие ACTIVE членства в текущей команде |
| LEFT/REMOVED из этой команды | Разрешено новое внешнее назначение, строго новее изменения членства; старое назначение недостаточно |
| Исторический SUSPENDED | Внешнее hiring назначение запрещено; публичный candidate admission по P1.5 сохраняется |
| PERSONAL | Ручной UUID enabled HR; searchable каталог общих активных команд без глобального поиска |
| Гостевой interviewer PERSONAL | Ручной UUID через room credentials, без authenticated `/me` preview/catalog; TEAM каталог этим не открывается |
| Гость по публичной ссылке PERSONAL/TEAM | Входит кандидатом; хост может явно назначить interviewer и вернуть candidate в этой комнате, без аккаунта и team membership |

## Требования

- **R-01. TEAM-приглашение:** управляющий создаёт внешнее назначение атомарно при
  подготовке интервью или позже из комнаты. Повтор не создаёт дубль. Интерфейс
  использует async UUID selector с подтверждением найденного пользователя, без
  выбора нанимающих из состава своей команды и без глобального каталога.
- **R-02. Проверка UUID:** preview с optional `teamId` требует ACTIVE автора
  этой команды. Ответ содержит только имя и нормализованный UUID найденного
  человека; активный коллега не предлагается как внешний нанимающий.
- **R-03. Область:** внешнему нанимающему доступны только назначенные интервью/
  кандидаты в личном кабинете. Назначение не даёт team membership и доступ к
  остальным кандидатам. Явный внешний interviewer сохраняет назначенную роль
  согласно актуальной серверной проверке, не через устаревший owner token.
- **R-04. Отзыв:** снятие внешнего назначения убирает кандидата из его кабинета
  и снимает interviewer authority, сохраняя вход по ссылке как candidate.
  Не снимает защищённого owner. Изменение видно в двух вкладках и после reconnect;
  self-removal закрывает manager panel. Уход коллеги регулирует P3.1.
- **R-05. Гонки:** pending/failure/retry не создают дублей. Поздние ответы после
  demotion/смены контекста не возвращают роль и не переводят комнату в terminal
  ошибочно; актуальный `410` означает terminal. Pending private данные очищаются
  и не появляются при повторном открытии. Отложенный callback чата не восстанавливает
  снятое назначение; authority перепроверяется после lock wait по P1.5.
- **R-06. Сведения из списка:** owner/interviewer открывает «Кандидат и нанимающие»
  из PERSONAL карточки, а ACTIVE коллега — объединённый «Редактировать интервью»
  из TEAM-карточки по P1.5 R-14, без realtime join. Сохраняются metadata revision,
  имя кандидата/должность/МСК дата, UUID и снятие HR. TEAM выбор следует R-01,
  PERSONAL каталог — таблице выше. Кандидату действие недоступно и на сервере.
- **R-07. Диалог:** конфликт/сетевая ошибка сохраняют черновик; смена аккаунта/
  команды отменяет запросы и закрывает старую форму. Изменения видны после
  закрытия/reload и в комнате. В TEAM название и сведения сохраняются атомарно
  через общий редактор P1.5; PERSONAL сохраняет отдельный карандаш. Внешние
  назначения применяются отдельными успешными действиями добавления/снятия;
  закрытие общего TEAM редактора не отменяет уже подтверждённое назначение.
  Поисковый
  селектор UUID и найденный результат для явного выбора по R-02 доступны при
  прокрутке, не перекрываются нижними действиями
  в обеих темах на 1366/768. Введённый UUID и найденный результат сохраняются
  при потере фокуса, Escape и удалении другого назначенного нанимающего;
  явное удаление текста, успешный выбор и смена аккаунта/команды очищают
  соответствующий черновик. Закрытие и focus сохраняются по UI.2.
- **R-08. Изоляция:** назначение не создаёт HR tracking через candidate admission,
  не раскрывает чужие private notes и не открывает TEAM management в простой
  converted PERSONAL→TEAM комнате. Возвращение к допустимой interviewer роли
  восстанавливает только её разрешённые manager поверхности.
- **R-09. Гостевая роль:** хост назначает присутствующему гостю доступную роль
  interviewer/candidate сразу после публичного входа в PERSONAL или TEAM комнату.
  Отсутствие аккаунта не блокирует назначение. Явное назначение гостя действует
  только для этой комнаты и её текущего пространства; reconnect сохраняет
  действующее назначение через серверную reconnect capability, без раскрытия
  секрета в SSE или сохранённых данных. Отзыв немедленно закрывает private
  поверхности и записи, старый reconnect не возвращает роль сам. Хост может
  повторно явно назначить interviewer тому же присутствующему гостю. PERSONAL
  capability после переноса комнаты в TEAM не даёт управление: нужен новый
  candidate admission и новое явное назначение. Кандидат не назначает роли,
  owner через это действие не назначается; прежние expiry/restart ограничения
  reconnect capability сохраняются.

| ID | Требования | Сценарий → результат | Проверка |
| --- | --- | --- | --- |
| AC-01 | R-01–R-03 | Внешний enabled UUID → одно назначение; ACTIVE коллега/disabled/чужой автор preview → отказ | Hiring preview/role integration + browser |
| AC-02 | R-03–R-04 | Внешний HR → только его интервью; снятие → исчезновение кандидата/manager данных в двух вкладках, вход candidate сохранён | HR removal integration + E2E |
