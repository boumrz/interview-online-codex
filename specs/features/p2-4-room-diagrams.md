# P2.4 — совместные схемы в комнате

Статус: реализовано и технически проверено, независимые обзоры без блокирующих
замечаний. Продуктовый просмотр ожидается, функция выключена по умолчанию.
Актуализировано: 2026-11-13. Разворачивание сохраняет редактор и историю;
native анимации отключены. Для AC-14 в Chromium проверены панель инструментов
у верхней границы при ширине 390–1440 px, добавление прямоугольника из палитры,
отмена и повтор. На панели комнаты с тестовым API проверены разворачивание,
возврат и скачивание .drawio, SVG и PNG. Для AC-13 и AC-15 в Chromium проверены применение своего цвета к новым фигурам,
подписям, связям и перу, сохранение выделения и Undo, раскладка панели и управление меню с клавиатуры. В iframe
высотой 307 px список масштаба прокручивается под панелью, выбранные 400%
применяются. Контекстное меню холста открывается у указателя. Сквозная проверка с PostgreSQL дошла до запуска Chromium,
который заблокировала macOS. TypeScript, production-сборка и 19 тестов интеграции draw.io
на уровне модулей прошли. Предыдущая проверка R-13 / AC-12: реальный motion
contract и 6 diagram E2E — PASS, включая Modal и новую левую панель.
Текущее название «Редактор диаграмм» отдельно проверено native browser E2E:
1/1 PASS у управляющего и кандидата, включая читаемость полного названия и
разворачивание обоих холстов. Селектор шириной 330px ограничен шириной контейнера;
TypeScript — PASS. Эта текстовая правка проверена целевым прогоном.
Предыдущий полный снимок и его границы — в
[отчёте 12.11](../references/2026-11-12-full-regression-tablet-input.md).

Результат: кандидат и интервьюеры строят архитектуру и свободные наброски в общей
рабочей области интервью, сохраняют схему и возвращаются к ней после встречи.

## Границы

- Входит: совместная схема для каждой задачи комнаты, режим «Редактор диаграмм» рядом с Code/Markdown,
  готовые архитектурные фигуры и свободные наброски, одновременная работа,
  сохранение, восстановление и экспорт подтверждённого документа.
- Основной редактор — draw.io с привычным интерфейсом; его статические файлы
  размещаются в существующем frontend InterHub. Дополнительные платформы,
  отдельные сервисы синхронизации и платные интеграции исключены пользователем.
  React Flow с собственным UI остаётся запасным выбором после конкретного
  непрохождения draw.io технических критериев; критерии не ослабляются.
- Библиотечные заготовки, приватные эталоны, AI-генерация,
  пользовательская загрузка изображений и новая mobile-матрица не входят.
- Общий режим и локальная геометрия: [P2.1 R-06–R-08](p2-1-room-layout-modes.md),
  [P0.3](p0-3-room-panels.md). Актуальные TEAM права: [P1.5](p1-5-team-interview-creation.md);
  назначения: [P2.3](p2-3-room-assignments.md); lifecycle: [P3.3](p3-3-interview-result.md).
- [Исследование и этапы](../../plans/interview-architecture-diagrams.md),
  [макеты состояний и потока](../../plans/interview-architecture-diagrams/storyboard.html).

## Сценарии и требования

- **R-01. Общая рабочая область:** при включённой функции менеджер выбирает
  «Редактор диаграмм» в существующем селекторе над редактором. Это отображаемое название;
  API и сохранённый ключ режима остаются `diagram`. Подтверждение явно сообщает,
  что рабочая область изменится у кандидата и всех интервьюеров. Отмена ничего
  не отправляет; конфликт версии показывает актуальный режим. Кандидат видит
  режим, но не меняет его. Это расширение P2.1 R-08, а не пятая боковая вкладка.
- **R-02. Схема выбранной задачи.** У каждой задачи есть свой документ с постоянным
  UUID, привязанный к `room_tasks.id`. Управляющий может готовить схему другой
  задачи приватно. Кандидат видит и редактирует схему опубликованной задачи в пределах
  своей роли. При публикации участники открывают сохранённую схему этой задачи.
  Перестановка сохраняет привязки. После переключения ожидающие правки относятся
  к исходной задаче. В комнате без задач доступна общая схема.
- **R-03. Оба способа рисования:** в одном документе доступны готовые фигуры,
  соединения, подписи, группировка, перемещение, изменение размеров, удаление,
  собственная отмена и свободные поясняющие наброски. Добавленные фигуры разных
  участников имеют разные ID. Для native freehand draw.io сохраняется возможность
  перемещать и менять размер/стиль объекта; редактирование точек штриха не обещается.
  Первый выпуск использует одну бесконечную страницу без вкладок страниц.
  В комнате и на весь экран редактор начинается с панели инструментов. Строка
  меню draw.io («Файл», «Правка», «Вид» и остальные разделы) скрыта и не занимает
  места. Палитра фигур, связи, отмена и повтор доступны в редакторе; статус
  сохранения и скачивание подтверждённой схемы доступны в панели комнаты.
  Выпадающий список инструмента открывается под рядом кнопок. При малой высоте
  длинный список прокручивается, кнопка выбора и соседние инструменты остаются видны.
  Zoom, grid и другие настройки представления действуют локально; изменения
  оформления без структурного native patch не заменяют общий документ.
  В проверенной 32.6.10 свободный штрих представлен native `shape=stencil(...)`
  внутри обычной фигуры и сохраняется тем же путём, что архитектурные блоки.
- **R-04. Одновременная работа:** активные кандидат и управляющие видят принятые
  изменения друг друга; конкурентные изменения разных объектов не теряются.
  Удаление против перемещения, изменение подписи против геометрии и привязки
  соединений имеют воспроизводимый результат, одинаковый у всех участников.
  Локальный Undo не отменяет принятую чужую операцию.
- **R-05. Подтверждённое хранение:** «Сохранено» означает запись документа либо
  восстанавливаемого снимка и упорядоченных операций в PostgreSQL. Доставка
  события или HTTP-ответ до durable commit не выдаются за сохранение. После ухода
  всех участников и рестарта сервера документ восстанавливается без другого
  подключённого редактора; late join получает то же подтверждённое состояние.
- **R-06. Непрерывность:** Code → Редактор диаграмм → Markdown → Редактор диаграмм, вкладки и resize
  сохраняют документы, допустимый фокус, локальный вид холста, историю и очереди
  отправки. Условие задания доступно в режиме схемы по геометрии Code. Четыре
  вспомогательные вкладки P0.3 сохраняются; на узкой раскладке действует существующая
  заметная кнопка возврата. Desktop/tablet, обе темы и масштаб 100–200%.
- **R-07. Понятные состояния:** при первой загрузке виден статус подготовки,
  при отсутствии содержимого — пустой холст; при изменениях — «Сохранение…»,
  после подтверждения последней правки — «Сохранено». Оба текста видны сразу после кнопки
  «Скачать» и занимают одно и то же место. При серии правок подтверждение появляется
  после короткой паузы, положение холста и кнопок остаётся постоянным. Разрыв показывает восстановление связи
  и отсутствие подтверждения новых правок. Ошибка загрузки/сохранения остаётся
  видимой и допускает явный повтор; незавершённая отправка не очищает документ.
  Постоянный отказ валидации останавливает проблемную очередь, сохраняя локальный
  документ. Доступно «Вернуться к сохранённой схеме»; только явное подтверждение
  «Загрузить сохранённую» удаляет несохранённые изменения этой вкладки и открывает
  принятую сервером версию. Отмена оставляет ввод и очередь.
- **R-08. Права:** чтение, запись и экспорт используют текущий доступ комнаты,
  независимо от client readOnly и подменённого идентификатора. Finished кандидат
  только смотрит; менеджер продолжает разрешённое редактирование, не возобновляя
  интервью. Frozen блокирует изменение всем; archived соблюдает P3.3. Отзыв роли,
  членства или доступа останавливает новые и queued записи, очищает защищённый
  контекст; поздние HTTP/SSE/iframe ответы не возвращают данные или права.
- **R-09. Экспорт и результат:** доступный читателю native `.drawio`, PNG и SVG
  строятся из подтверждённого документа, а не неподтверждённого локального ввода.
  Слева над холстом расположены кнопки «Ваш цвет» и «Скачать», у правого края —
  «На весь экран» или «Вернуться в комнату». На узкой панели разворачивание
  доступно по иконке с тем же доступным именем. Меню доступно с клавиатуры, в режиме
  просмотра и на весь экран; при потере связи скачивание недоступно.
  Native-файл открывается для дальнейшего редактирования; файл изображения реально
  читается. Подготовка и ошибки заметны; повтор не дублирует скачивание. В finished
  доступна актуальная подтверждённая схема; неизменяемый снимок момента завершения
  в этот выпуск не входит.
  Если общий режим finished комнаты — Code/Markdown, кандидат открывает локальный
  просмотр действием «Посмотреть схему» и возвращается «К материалам интервью».
  Эти действия не меняют общий режим и не дают кандидату право его переключать.
- **R-10. Ограничения редактора:** загрузка внешних изображений, сторонние plugins
  и небезопасные ссылки не расширяют доступ и не отправляют содержимое комнаты
  внешним сервисам. Native freehand-представление допускается при проверке формата
  и размера. Некорректные XML/patch, превышение лимитов и неизвестный документ
  отклоняются без повреждения прежнего состояния. Токены и содержимое схемы не
  попадают в логи, recovery storage или URL iframe.
- **R-11. Управляемое включение:** `FEATURE_ROOM_DIAGRAMS_ENABLED=false` по умолчанию в backend
  и frontend до технического gate и независимого scoped review. При выключенной
  функции старые Code/Markdown работают как раньше; прямой запрос записи схемы
  не обходит выключение. Проверка проводится в изолированном окружении без
  запуска, остановки или перезапуска пользовательского приложения.
  Для разрешённой выкладки оператор включает оба холста существующим deploy script
  по [P6 R-10](p6-release-gates.md). Frontend требует пересборки, одного restart недостаточно.
- **R-12. Пространство для проектирования:** любой участник, включая readonly,
  может развернуть схему кнопкой «На весь экран». Холст занимает всю ширину и
  высоту за вычетом своей компактной панели; шапка комнаты, условие и боковые
  области остаются за ним и недоступны для фокуса. «Вернуться в комнату» всегда
  видна и доступна клавиатурой, в том числе на коротком экране; возврат
  восстанавливает прежнюю раскладку, условие и выбранную вспомогательную вкладку.
  Тот же iframe остаётся смонтированным: масштаб, выделение, история отмены и
  отправка правок сохраняются. Разворачивание локально, не меняет общий режим
  или вид другого участника и сбрасывается при уходе из «Схемы»/контекста комнаты.
  Восстановление отклонённой правки доступно поверх развёрнутого холста.
  В обычной раскладке боковую панель можно скрыть отдельно по [P0.3 R-06](p0-3-room-panels.md),
  а условие — свернуть существующей кнопкой. Новые сервисы и браузерный Fullscreen
  API для этого не требуются; Escape сохраняет native поведение редактора.
- **R-13. Мгновенная смена геометрии:** сворачивание и разворачивание схемы не
  запускает анимации/переходы оболочки или native draw.io панелей. Native
  адаптация к ширине выполняется без промежуточных анимированных размеров;
  масштаб, история и сам iframe сохраняются. Отключение движения ограничено
  встроенным редактором и его управляющей областью.

- **R-14. Цвет участника:** сервер назначает каждому логическому участнику комнаты
  уникальный цвет по умолчанию для новых контуров, линий, стрелок и текста; тот же
  цвет применяется на [доске](p2-5-room-whiteboard.md). Назначение не зависит от
  имени, роли, порядка входа текущего списка или клиентского хеша. Повторный вход,
  несколько вкладок одного участника, переподключение и перезапуск backend сохраняют
  назначение; уход не освобождает цвет для другого автора этой комнаты. Начальная
  палитра дополняется новыми цветами без циклического повторения. Цвет виден рядом
  с именем участника в доступном ему списке. На редактируемом холсте кнопка
  «Ваш цвет» применяет назначенный цвет к следующим фигурам, связям, подписям
  и штрихам, сохраняя выделение, инструмент и историю. В режиме просмотра
  образец цвета виден, кнопка отключена.
  Применение значения по умолчанию
  не перекрашивает сохранённые/чужие объекты и не сбрасывает ручной выбор цвета
  при remote update, смене темы, режима или геометрии. Native выбор другого цвета
  доступен; уникальность гарантируется для назначенных значений по умолчанию.
  Цвет помогает визуально различать авторов, но не является неизменяемой подписью
  объекта и не меняет права доступа.

## Права и данные

Управляющий — актор, для которого текущий room access разрешает management;
дополнительного owner-only ограничения у схем нет.

| Состояние/актор | Чтение и экспорт | Изменение схемы | Смена общего режима |
| --- | --- | --- | --- |
| active, управляющий | Да по текущему доступу | Да | Да с подтверждением |
| active, кандидат | Да по текущему доступу | Да | Нет |
| active, зритель | По текущему доступу | Нет | Нет |
| finished, управляющий | Да по текущему доступу | Да | По P2.1/P3.3 |
| finished, кандидат/зритель | По текущему доступу | Нет, включая прежнюю очередь | Нет |
| frozen, любой актор | По текущему доступу | Нет | По существующему lifecycle |
| archived / доступ отозван | По P1.5/P3.3; публичный admission закрыт | Нет | Нет |

Долговременно хранятся UUID документа/комнаты, формат и версия редактора/схемы,
подтверждённое содержимое, последовательность/ревизия и необходимые операции
восстановления. Идентичность не зависит от номера задачи. Положение холста,
масштаб, выделение, инструмент и курсоры не являются общим сохранённым документом.
Назначение цвета хранится отдельно как идентичность участника внутри комнаты и HEX;
оно не содержит имени, credential или содержания рисунков и удаляется с комнатой.
Миграция V38 закрепляет прежнюю схему комнаты за опубликованной задачей. Если её
номер недействителен, выбирается первая задача по порядку. Комната без задач сохраняет
схему до добавления первой задачи, которая наследует её. UUID, XML, последовательность
и квитанции операций сохраняются. Остальные задачи начинают с пустой схемы.
Удаление задачи удаляет её схему и квитанции, удаление комнаты — все её схемы.

## Ошибки, восстановление и инварианты

- Каждая операция имеет уникальную идентичность в контексте документа. Повтор
  после потерянного ответа возвращает прежний результат без второй записи.
  Конкурентное принятие имеет серверный порядок; повтор/перестановка доставки
  не удваивает действия, а пропуск выявляется до подтверждения синхронизации.
- XML-снимок и последовательность представляют подтверждённый документ; журнал
  принятых операций/квитанций обеспечивает догрузку изменений и дедупликацию.
  Снимок клиента не перезаписывает более новую последовательность. Компактация,
  если есть, сохраняет эквивалентность replay и не удаляет неподтверждённые операции.
- После reconnect сначала восстанавливаются доступ и актуальный документ,
  затем согласуются ещё разрешённые локальные изменения. Контекст старой комнаты,
  аккаунта или UUID не пишет в новый. Поздний ACK не очищает следующий ввод.
  Новое SSE соединение не считается подтверждением новой authority до state_sync.
  В этот промежуток diagram-запросы ждут свежего event proof. Отказ по старому
  proof после замены подключения не выдаётся за подтверждённый revoke и не
  удаляет очередь; отказ по текущему proof обрабатывается по R-08.
- Checksum mismatch, XML-only событие и разрыв baseline обрабатываются явным
  восстановлением; тихая полная замена чужой сцены последним автором неприемлема.
- Блокировки/транзакции не удерживаются во время сетевой SSE отправки медленному
  клиенту. Многопроцессная маршрутизация остаётся общей deployment-задачей SPEC.

## Реализация и проверка пригодности

Статический draw.io по `/drawio/` должен быть закреплён на проверенной версии, для native
embed diffSync — не ниже 30.2.7. Проверка должна подтвердить реальные `patch`,
`getDiff/resetDiff`, XML-only события, отсутствие echo loop, уникальные ID,
собственный Undo, разрыв/восстановление, чтение и replay после рестарта.
Свой Node/WebSocket-сервис, CryptPad и платный Pro-код не добавляются.
Цвет новых фигур/связей задаётся через native configure; отдельный локальный
startup adapter для закреплённого 32.6.10 один раз задаёт цвет freehand,
который upstream хранит отдельно. Adapter не меняет vendor-файлы, существующие
объекты или ручной выбор и сохраняет проверки окна/origin текущего bridge.

Источник истины — серверное принятие и долговременная запись; клиентский adapter
применяет механизм объединения редактора. Отдельный diagram-модуль не хранится
строкой в Yjs `room-code`. Предварительно согласован следующий контракт:

| Операция | Контракт |
| --- | --- |
| GET `/api/rooms/{inviteCode}/diagram?taskId=…&sessionId=…&afterSequence=…` | Возвращает `{taskId, diagramId, sequence, xml, canEdit, editor: "drawio", schemaVersion: 1, operations, requiresSnapshot}`; `sessionId` и `afterSequence` необязательны; операция содержит `{sequence, operationId, sessionId, patch?, xml, checksum?}` |
| POST `/api/rooms/{inviteCode}/diagram/changes?taskId=…&sessionId=…` | Принимает `{diagramId, operationId: UUID, baseSequence, xml, patch?, checksum?}`; `sessionId` обязателен; проверяет текущий доступ и lifecycle; атомарно сохраняет XML и квитанцию операции при совпадении sequence; ответ — принятая операция и `diagramId` |
| Конфликт | `409` не считается сохранением: клиент читает актуальный документ, согласует ожидающие native patches и повторяет разрешённое намерение, не подменяя новую сцену старым XML |
| SSE `diagram_changed` | После commit передаёт только `{taskId, diagramId, sequence}`. Для опубликованной задачи сигнал получают участники комнаты, для приватной — подписанные на неё управляющие. Клиент догружает правки своего документа через GET с проверкой доступа. |

В обоих запросах редактор указывает `taskId` выбранной задачи. Пустое значение
допустимо только в комнате без задач. При отсутствии параметра сервер выбирает
опубликованную задачу или схему комнаты без задач для совместимости со старыми клиентами.
Перед загрузкой фигур редактор сверяет `taskId` ответа с выбранной задачей.
Если сервер вернул документ другой задачи или прежний общий документ без этого поля,
редактор сообщает об ошибке и блокирует редактирование.

Авторизация запросов следует текущему стилю Room API: `Authorization: Bearer`,
`X-Room-Owner-Token`, `X-Room-Interviewer-Token`, `X-Room-Event-Token` по действующему
контексту. Credentials передаются только headers, не URL редактора. Повтор с прежним
`operationId` не пишет повторно и возвращает квитанцию исходного результата.
Backend и frontend проверяют `FEATURE_ROOM_DIAGRAMS_ENABLED`; assets по `/drawio/`
не содержат credentials. Окончательные лимиты и достигнутая совместимость
обновляются по результатам технической проверки; эксперимент не доказывает
готовность production API.

R-14 / AC-13 реализованы и проверены:9 PostgreSQL,3 native adapter unit и
итоговый production native color E2E — PASS. Цвета новых native фигур, связей и
freehand сохранены явно; у обоих участников прежние объекты не перекрашиваются.
Смена темы/режима, ручной выбор и Undo проверены в общем прогоне.
Независимые scoped reviews — PASS/approve.
