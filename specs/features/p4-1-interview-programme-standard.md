# P4.1 — стандарт задач трека/вакансии

Статус: реализована; проверки по прежним evidence. Актуализировано: 2026-10-02.
Результат: OWNER/ADMIN задаёт действующий состав задач трека/вакансии,
а подготовка интервью использует его как исходный выбранный состав.

## Требования

- **R-01. Происхождение:** отсутствие программы — `programme: null`. Вакансия
  без собственной программы наследует программу трека (`origin: TRACK`);
  собственная опубликованная программа имеет `origin: VACANCY`. UI показывает
  происхождение, версию, статус и обязательность выбранных задач понятным языком.
- **R-02. Сохранение:** редактор открывается диалогом; поисковый MultiSelect
  выбирает состав, порядок задач задаётся отдельно. Сохранение draft и публикация
  используют текущую revision; сохранение состава сразу делает программу
  действующей. Архивная программа возвращается в действие через редактор.
  Отдельные кнопки публикации/архивации в карточке не показываются; действующая
  программа подписана «Активны».
- **R-03. Сервер:** OWNER/ADMIN меняет стандарт; MEMBER не может обходить UI.
  Draft-save требует непустые активные задачи своей команды без дублей.
  Несовпавшая revision → `409 TEAM_PROGRAMME_REVISION_CONFLICT` без stale overwrite.
- **R-04. Версии:** revision защищает конкурентное редактирование; publish
  увеличивает version для создания интервью. Legacy archive/restore меняют
  status/revision, не подменяют pin version. Исторические API lifecycle не
  требуют возвращать отменённые UI-кнопки.
- **R-05. Подготовка:** опубликованные задачи выбраны по умолчанию; организатор
  может снять их или добавить extras перед созданием. Оставленные программные
  задачи становятся mandatory в комнате; это не требование включить всю программу.
  Pin/snapshot и конфликт устаревшего preview определены [P4.2](p4-2-mandatory-programme-interview.md).
- **R-06. Недействующий стандарт:** попытка создания по архивной resolved программе
  отклоняется до записи комнаты (`409 TEAM_PROGRAMME_ARCHIVED`); неопубликованная
  программа — отдельный `TEAM_PROGRAMME_NOT_PUBLISHED`. UI объясняет отказ.

## Реализация и проверка

Программа хранится в `team_interview_programmes`/`team_interview_programme_items`;
проекция включает origin, targetType/targetId, status, version, revision,
mandatory и упорядоченные задачи. Треки/вакансии — [P1.2](p1-2-tracks-vacancies.md),
доступ к TEAM-интервью — [P1.5](p1-5-team-interview-creation.md).

| ID | Требования | Сценарий → результат | Проверка |
| --- | --- | --- | --- |
| AC-01 | R-01 | Вакансия без/с собственной программой → верное наследование/источник; отсутствующая → null | Track/vacancy integration |
| AC-02 | R-02–R-04 | OWNER/ADMIN сохраняет → действующая новая version; stale/MEMBER/дубликат → отказ без overwrite | Revision integration + editor E2E |
| AC-03 | R-05–R-06 | Снятие default задачи допускается; archive/draft/stale preview не создаёт комнату | Creation integration + P4.2 flow |

и [UI evidence](../references/ui-2-verification-2026-09-27.md).
