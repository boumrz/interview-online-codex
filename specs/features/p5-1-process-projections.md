### P5.1 Проекции процессов

Цель: сохранить безопасные проекции процессов для каталога участников и API.

Реализовано:

- distinct process projection по grants/epochs;
- member directory process labels;
- API «Мои интервью в этом процессе»;
- caller-only filtering.

Проверка: backend PostgreSQL integration для собственных интервью и безопасных меток коллег, каталог участников; browser E2E для меток и отсутствия повторной панели на странице интервью; frontend typecheck.

Контракт:

- Процесс — пара `trackId`/`vacancyId` существующего командного интервью; интервью без трека не создаёт процесс. Наличие вакансии уточняет процесс трека.
- `GET /api/teams/{teamId}/processes` возвращает только разные пары из неархивных интервью, на которые у вызывающего есть действующее назначение и активное членство.
- `GET /api/teams/{teamId}/processes/interviews?trackId=…&vacancyId=…` возвращает только собственные назначенные интервью выбранной пары. Для процесса трека без вакансии параметр `vacancyId` отсутствует. Недоступная пара даёт пустой список без различения неизвестной и чужой пары.
- В каталоге участников `processes` содержит только названия трека и вакансии и их идентификаторы, выведенные из действующих назначений каждого активного сотрудника. Комнаты, кандидаты, даты, результаты и числа интервью туда не попадают. При удалении назначения или членства метка исчезает.

Acceptance:

- метка процесса у коллеги не раскрывает его кандидатов, комнаты, даты, результаты и counts;
- страница командных интервью не повторяет карточки в отдельной панели процессов; вместо неё единый список и фильтр «Мои интервью» из спецификации P1.5.
