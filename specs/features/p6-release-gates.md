## P6 — финальный выпуск

Цель: подтвердить весь путь Atlas end-to-end и включить только готовую функциональность.

Что сделать:

- сквозной сценарий: приглашение → трек/вакансия → библиотека/набор → программа → интервью → комната → результат/экспорт → merge;
- PostgreSQL upgrade/fresh install;
- feature-flag off с существующими TEAM rows;
- нагрузочные и security checks;
- финальная UX/product acceptance.

Acceptance:

- все основные пользовательские потребности закрыты работающим сценарием;
- нет P0/P1 security blockers;
- нет реальных кандидатских данных в evidence;
- feature flags включаются только для прошедших release gates.

### Состояние на 2026-09-23

Функциональный путь реализован и доступен для локальной отладки в одном
backend-процессе при включённых `FEATURE_TEAM_WORKSPACES` и
`FEATURE_TEAM_MERGE_COMMIT`. Проверено:

- командный browser E2E набор: 41 сценарий пройден;
- после защиты повторного входа отдельно перепроверены browser сценарии плана,
  commit объединения и отзыва доступа: `3/3`;
- PostgreSQL integration для merge, доступа к командам, candidate activity и
  жизненного цикла realtime-подключений: 30 серверных проверок пройдено;
- миграции до v26 на чистой базе и upgrade существующей команды;
- режим с выключенным merge flag при существующих командных данных;
- отказ commit при открытом SSE комнаты, ожидающих room writes, устаревшем
  плане, конфликте состава и отозванном доступе;
- desktop/tablet и zoom 100/125/150/200% для layout комнаты.
- полный browser E2E набор комнаты с диагностикой жизненного цикла SSE:
  19 сценариев пройдено; резкое закрытие освобождает серверную сессию;
- старый токен комнаты не может закрыть заменившее его подключение; тестовое
  окружение использует тот же `open-in-view: false`, что и рабочее.

### Техническое завершение P6

- PostgreSQL migrations v27–v28 добавляют общий учёт активности комнат и
  индекс для удаления истёкших записей. Commit
  проверяет аренды всех backend-процессов после блокировки строк комнат;
  admission, выход, heartbeat, истечение аренды и ожидающие записи покрыты
  серверными проверками. Аварийно оставленная аренда истекает через 60 секунд
  и удаляется при следующей периодической сверке.
- Проверка на PostgreSQL с 40 параллельными SSE admissions подтверждает одну
  аренду процесса на комнату и освобождение после закрытия. Отдельная проверка
  моделирует комнату другого backend-инстанса и подтверждает отказ commit до
  истечения её аренды.
- Объединённый browser E2E сценарий прошёл путь приглашение → материалы и
  программа → интервью и комната → результат и XLSX → согласование и commit
  объединения → старая ссылка. Использованы только синтетические данные.
- Отдельный browser/API сценарий с двумя backend-процессами и общей
  PostgreSQL-схемой подтвердил: SSE на втором процессе запрещает commit на
  первом до закрытия stream (`1/1`).
- Итоговые проверки: backend PostgreSQL/H2 `36/36`; полный командный browser
  E2E `42/42`; полный E2E комнаты с диагностикой SSE `19/19`; навигация и
  матрица размеров/zoom `104/104`; frontend typecheck и сборка с обоими
  флагами прошли.
- Локальный backend и frontend запущены с обоими флагами для просмотра;
  default-конфигурация по-прежнему оставляет флаги выключенными.

Разработка и техническая проверка P6 завершены для локального просмотра.
После просмотра пользователем остаётся продуктовая приёмка и исправление
найденных им дефектов. При выкладке нескольких backend-процессов требуется
маршрутизация комнаты к одному realtime-хосту либо отдельный межпроцессный
транспорт событий: общая аренда защищает commit объединения, но сама по себе
не передаёт события редактора между процессами.

### Корректировка после продуктовой проверки 2026-09-23

Исторические результаты выше относятся к прежнему составу продукта. Аудит,
новые приостановки и объединение команд сняты с пользовательского сценария и
их публичные маршруты удалены. Локальный frontend доступен на
`http://localhost:5174/`, backend — на `http://localhost:8080/`.

Целевые проверки текущей редакции прошли: frontend typecheck и сборка,
PostgreSQL integration для командных интервью и каталога участников,
интеграционный набор повторно используемой ссылки приглашения, браузерная
проверка однострочной навигации и Markdown-сценария с кандидатом и
перезагрузкой. На локальном API одна ссылка добавила двух участников;
перевыпуск сохранил одну запись и закрыл старый адрес. Удалённые публичные
маршруты ответили 404.

Общий исторический backend test suite целиком не является зелёным gate:
часть старых H2-фикстур нарушает ограничения БД, а совместный запуск множества
Spring-контекстов исчерпывает память. Для текущей продуктовой правки
используются перечисленные целевые проверки; общую стабилизацию тестового
набора следует вести отдельно от приёмки интерфейса.
