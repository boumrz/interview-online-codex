# UI.1 — Ant Design v6 и единая визуальная система

Статус: **реализована на S01–S16; техническая приёмка частичная, продуктовая ожидается**.
Актуализировано: 2026-10-02. Подробности покрытия и ограничений — в §12.

## 1. Назначение и порядок чтения

Сильно обновить визуальную составляющую InterHub: стандартные элементы интерфейса должны использовать Ant Design v6, общую систему **светлой и тёмной тем с переключением**, согласованные размеры и состояния. Сохранить работающие пользовательские сценарии, данные и серверные ограничения.

Это действующий визуальный и технический контракт. Основная миграция выполнена; сохранённые результаты не доказывают всю матрицу приёмки. Последующие замечания по удобству сведены в [UI.2](ui-2-usability-theme-polish.md); применимые актуальные правила включены ниже. Нормализация документа не является новым тестом приложения или продуктовой приёмкой.

Порядок чтения: [SPEC.md](../../SPEC.md) → owning feature → применимые разделы этого договора/UI.2 → нужные исходники и проверки. Для обычной правки не читать весь архив. Правила поддержания договора — [specs/README.md](../README.md); статус и краткое coverage обновлять в §12 и SPEC.md, подробные отчёты хранить в references.

Приоритет решений:

1. Последние явные указания пользователя.
2. Текущие owning specs P0–P6 — поведение, права и жизненные циклы; UI.2 — текущие уточнения удобства.
3. Этот документ — библиотека UI, палитра, геометрия, визуальные состояния и границы миграции.
4. Исходные вложения — значения исходных палитр; их технические ошибки исправляются по §4.
5. Исторические OpenSpec и старые разделы спецификаций — только справка.

Цвет главного действия задаётся primary выбранной темы из §4. Значение действий и доступность по ролям определяются owning feature. Текущий стандартный UI-стек — Ant Design v6, React + TypeScript + RTK/RTK Query + CSS Modules + Rspack; Mantine относится к прежней реализации. Остальной стек сохраняется.

## 2. Исходное состояние и границы

### 2.1. Состояние миграции и rationale

До миграции были смешаны Mantine 7, antd 5, Tabler, принудительная dark-тема и
несколько CSS/inline источников цветов. Поэтому нужен общий Ant theme context
для обычного DOM и порталов, единые токены и сохранение специализированного
CodeMirror/Yjs/SSE lifecycle. Исходный инвентарь и журнал сохранены в
[исторической редакции](../references/history/ui-1-antd-v6-design-system-2026-10-02.md).
По журналу S01–S16 переведены на Ant Design 6.6.5/@ant-design/icons 6.3.4,
Mantine/Tabler удалены; это прежний результат, без нового dependency audit.

### 2.2. Входит в доработку

- Все достижимые экраны frontend, их формы, меню, таблицы, диалоги, уведомления, loading/error/empty/denied состояния.
- Ant Design v6 как стандартная UI-библиотека и согласованный набор иконок; завершённая миграция без возвращения Mantine.
- Нормализация приложенных цветов, размеров и типографики; единый источник токенов для Ant Design и CSS Modules.
- Светлая и тёмная оболочки с переключением. Светлая тема использует primary `#642eff`; тёмная — палитру §4.5. Код, Markdown, gutter, selection и preview также следуют выбранной теме без потери editor/document/undo state; системная тема и ручной приоритет определены §4.6.
- Desktop/tablet, короткое окно и существующая матрица масштабирования; клавиатура, читаемость, фокус.
- Визуальные проверки, адаптация устаревших цветовых assertions, регрессия затронутых сценариев.

### 2.3. Не входит

- Смена React, RTK, маршрутизатора, сборщика, backend, БД, транспорта SSE/POST, CRDT или редактора CodeMirror.
- Новые бизнес-фичи, маршруты, API, изменения прав, новая система форм/кеширования/хранения черновиков.
- Запуск кода, terminal/stdout/stderr: такого сценария в текущем пользовательском редакторе нет; `outputPanel` не является основанием добавлять runner.
- Возврат аудита, объединения команд, новых приостановок, видимых Focus/Overview, вкладки «Редактор», отдельной повторной ленты «Мои процессы».
- Phone-first продукт, полная мобильная матрица, compact-mode preference. Поддерживаются desktop/tablet и системная тема с ручным приоритетом по §4.6.
- Переработка PDF/XLSX форматов, механизмов аналитики, CI или исправление всех исторических backend-тестов.
- Подключение чужих/недоступных файлов шрифтов, включение feature flags или изменение запущенного окружения пользователя.

## 4. Токены: нормативный контракт

### 4.1. Приложения и обнаруженные проблемы

Исходники сохранены без изменения в [каталоге входных материалов](../references/antd-v6/README.md).

- ThemeConfig ссылается на 303 уникальные CSS-переменные, включая неиспользуемые группы. CSS определяет 161 уникальную переменную. Совпадают только `--font-base` и семь `--size-*`; 295 ссылок отсутствуют. Это число относится ко всему входному фрагменту, не к числу реально отрисованных ошибок.
- Нет определений `--Colors-*`, контрольных высот, радиусов, breakpoint/font-size tokens; `getCssNumber` может получить `NaN`. `parseInt` также непригоден для дробных line-height.
- Есть повторные определения шрифтов и алиасов, несовпадающие семейства `SBSansText` / `SB Sans Text`, debug `console.log`, обращение к DOM при импорте, `@ts-expect-error`/`@ts-ignore`.
- `fontFamilyCode` ошибочно приравнен к пропорциональному UI-шрифту. Большинство component overrides закомментированы. Комментарий о light/dark не реализует переключение.
- Активные `Tag.colorBgSolid='#ff0'`, `hashed:false`, padding-workarounds и compact helper с CSS-строками вместо чисел не являются требованиями продукта. В рабочую тему их не переносить. Источником status-палитр служат конкретные CSS primitives, а не стандартные зелёный/оранжевый/красный seed из TypeScript-фрагмента.
- Нельзя одновременно считать `--size-md:16px` отступом из вложения и автоматически назначать его всем одноимённым derived-токенам Ant Design: одинаковое имя не доказывает одинаковую роль.

### 4.2. Единый источник

Используется один типизированный manifest конкретных значений (общие primitives/размеры и два semantic-набора light/dark), из которого строятся Ant ThemeConfig и CSS custom properties. Текущая область реализации — `frontend/src/features/theme/`; сохранять единый источник при последующих изменениях. Не поддерживать вручную независимые TS/CSS-таблицы значений.

Нормы:

- Сохранить **все конкретные исходные primitive-палитры** (`brand`, `gray`, `neutral`, `green`, `orange`, `red`, `blue`, `black`, `white`) и шкалы offset/size. Не менять их hex-значения при переносе. Неиспользуемые primitives допустимы как палитра.
- Отображать их в CSS с исходными именами, а прикладные роли — через `--app-*`. Компонентный CSS использует семантические роли, не случайные индексы палитры.
- Удалить дубли при нормализации шрифтов; legacy/deprecated aliases не использовать в новом UI. Для неоднозначного старого alias действует последнее CSS-объявление, но типографика нового интерфейса задаётся ниже.
- Не восстанавливать все 295 отсутствующих ссылок. Удалить неиспользуемые ссылки и overrides из рабочей темы. Не переопределённые токены Ant Design получает от `defaultAlgorithm` в light и `darkAlgorithm` в dark; явные semantic overrides имеют приоритет.
- Seed colors и числовые токены передавать конкретными значениями, без `var(...)` там, где алгоритм рассчитывает палитру/арифметику. CSS-переменные — выход системы темы, а не обязательный способ передать входные seed values.
- Чистое создание темы без `window`, `document`, `getComputedStyle`, скрытого CSS bootstrap и чтения DOM при импорте. Нет `NaN`, `undefined`, подавлений ошибок типов и debug-log.
- CSS подключается до отображения маршрутов. У Ant и пользовательских поверхностей совпадают токены с первого кадра; разрешённые CSS aliases не образуют циклов и не ссылаются на отсутствующие свойства.

Это решения данной спецификации на основе вложений, а не заявление, что пользователь прислал полный готовый набор semantic tokens.

Роли статусов в таблице обязательны для Tag/Alert/Badge и inline feedback. Остальные success/warning/info/error hover/border aliases вычисляет Ant algorithm; после вычисления проверить контраст реально используемых пар. Информационные и warning-иконки не должны теряться на фоне — при необходимости применять указанный цвет текста роли.

Не использовать `brand-400` `#766cf9` как заливку кнопки с обычным белым текстом: рассчитанный контраст около 3.97:1. Для white/primary-500 — около 6.22:1; `gray-700` на white — около 5.45:1. Значения — расчёт sRGB, проверять итоговый computed style.

Обязательное отображение ролей в Ant: primary/subtle/subtle-hover → `colorPrimary`, `colorPrimaryBg`, `colorPrimaryBgHover`; selected/selected-hover → `controlItemBgActive`, `controlItemBgActiveHover`; main → `colorText`, `colorTextHeading`, `colorTextBase`; secondary → `colorTextSecondary`, `colorTextDescription`; placeholder → `colorTextPlaceholder`; field border → `colorBorder`; divider → `colorBorderSecondary`, `colorSplit`. В light selected использует primary-subtle и primary-text. Аналогично явно задать status `color*`, `color*Text`, `color*Bg`, а не полагаться на совпадение алгоритма с CSS.

CSS bridge существующих имён: `--app-bg`=page, `--app-surface`=container, `--app-surface-soft`=alternative surface, `--app-border`=decorative divider, `--app-text`=main, `--app-muted`=secondary. Для controls добавить `--app-control-border`, `--app-primary`, `--app-primary-hover`, `--app-primary-active`, `--app-on-primary`, `--app-selected-bg`, `--app-selected-hover`, `--app-selected-text`, `--app-focus`. Остальные имена следуют роли, а не отдельной странице. Все эти значения в обеих темах выводятся из manifest; `--font-base`/`--font-code` следуют §4.4.

| Metadata | 13 px / 18 px, 400; не использовать для основного текста, ошибок или полей |
| Заголовок секции | 18 px / 24 px, 600 |
| Заголовок страницы | 24 px / 32 px, 600 |
| Публичный hero | 40 px / 48 px, 600; 32 / 40 при недостатке места |
| Code/editor | 14 px / 22 px; не уменьшать код, чтобы вместить панели |

SB Sans не поставляется вложениями и отсутствует среди UI-font assets проекта. Поэтому эта миграция сохраняет IBM Plex Sans/Mono; SB Sans не становится скрытой зависимостью. Возможная последующая замена требует разрешённых файлов и обновления спецификации. Не скачивать неизвестный файл. Fallback рассматривается как штатный и должен пройти ту же геометрию; новая лицензия/внешний font-hosting не требуется.

Размеры Ant передаются числами; fontSize/SM/LG/XL=15/13/16/20, lineHeight/SM/LG — unitless отношения `22/15`, `18/13`, `24/16`, fontWeightStrong=600. Для H1–H5 задать последовательно 24/32, 20/28, 18/24, 16/24, 14/22; heading line-height также передаётся отношением. Роли визуальной типографики не меняют смысловую иерархию h1–h6. Один semantic h1 на страницу.

Ant spacing mapping: paddingXXS/XS/SM/default/MD/LG/XL = 4/8/12/16/20/24/32; marginXXS/XS/SM/default/MD/LG/XL/XXL = 4/8/12/16/20/24/32/40. `sizeUnit=4`, `sizeStep=4`; остальные derived size tokens оставить алгоритму. Не подключать compactAlgorithm.

Breakpoints Ant сохраняются: xs=480, sm=576, md=768, lg=992, xl=1200, xxl=1600 px; связанные min/max не переопределять несогласованно. Комната выбирает раскладку по полезной геометрии существующей layout-функции, а не только по breakpoint окна.

### 4.6. Переключение, хранение и первый кадр

- Ровно два режима `light | dark`. Без ручного выбора применяется тема ОС (`prefers-color-scheme`) и отслеживаются её изменения. Ручной выбор сохраняется и переопределяет ОС; третья кнопка «Системная» не добавляется.
- Общий Ant `Button` с декоративной иконкой, постоянным accessible name **«Тёмная тема»** и `aria-pressed=(mode === 'dark')`. Tooltip показывает действие «Включить тёмную тему» / «Включить светлую тему». Space/Enter/мышь переключают один раз, focus остаётся; это `type=button`, не submit. Размер 36×36 px, coarse pointer 44×44.
- Место: последняя справа во всех шапках landing/login/invitation/personal/team/legacy/room; вне auth/join формы и отдельно от языка/публикации. Кнопка доступна кандидату без аккаунта. Для short viewport она остаётся в доступной полосе, даже если другая часть шапки скрывается. Место зарезервировано до измерения nav overflow; «Выйти» не обрезается.
- Настройка общая для браузера/origin, сохраняется при переходах, login/logout, смене аккаунта и команды. Один localStorage key **`interview-online:ui-theme`**, значение — только строка `light` либо `dark`, без JSON, account/room ID и любых секретов.
- До первого содержательного paint bootstrap в `frontend/public/index.html` проверяет значение через whitelist и `try/catch`, задаёт `html[data-theme]` и соответствующий `color-scheme`. Отсутствие, неизвестная строка или ошибка чтения → тема ОС, при недоступном системном определении — light. HTML/CSS fallback без JS — light. Обе CSS-темы доступны до рендера; React получает уже выбранное начальное значение, без промежуточного light в effect.
- Чистый token manifest не читает DOM; отдельный bootstrap имеет право читать storage/ставить атрибут. Данные цветов в bootstrap не дублируются вручную: ранний CSS выводится из общего manifest. Существующая CSP, если настроена в окружении, не ослабляется ради bootstrap.
- Переключение синхронно обновляет theme state и root attribute до следующего paint; без сетевого запроса, spinner, confirmation, toast или глобального CSS-перехода всех цветов. Ошибка записи storage не отменяет выбор в текущей вкладке; следующая загрузка применяет последнее доступное сохранённое значение либо системную тему.
- Между вкладками включена синхронизация через `storage`: valid значение применяется, удаление ключа/invalid → системная тема; listener не пишет значение обратно и не создаёт цикл. Свою вкладку обновлять напрямую, не ожидать собственного storage event. Storage failure не приводит к повторным уведомлениям или crash.
- Нужны стабильные immutable ThemeConfig двух режимов. Не менять `key`, `cssVar.key`, prefixCls, provider tree, Ant App DOM или route identity; не мутировать один объект на месте. Тема не перезапускает SSE, не создаёт комнату, не меняет revision/шаг/роль.
- Открытые Modal/Dropdown/Select/Tooltip/message/notification обновляются без сброса значений, ошибки, pending, focus и scroll. Кнопка за modal mask не становится доступной через обход focus trap. Проверка открытого modal проводится сменой темы из второй вкладки; normal outside-click closing dropdown не считается регрессией, закрытие из-за theme update — считается.
- CodeMirror, code blocks, Markdown, preview, gutter и selection используют выбранную тему, без постоянной dark-поверхности в light. Для theme-only изменения сохраняется тот же EditorView/Yjs binding. Не менее 20 переключений light↔dark в комнате не меняют draft/selection/scroll или число подключений.

## 5. Дизайн экранов и взаимодействий

### 5.1. Общая композиция

Направление — спокойный рабочий интерфейс для длительного интервью: нейтральные светлые/тёмные поверхности, чёткая типографика, primary выбранной темы, предсказуемые controls. Сильное изменение достигается общей системой поверхностей и иерархией, а не эффектами.

- Header: контекст/переключатель слева, разделы справа перед профилем/выходом, тема последняя справа. Бренд InterHub/IH, UUID/домены данных совместимы. Имя пользователя открывает профиль выбранного пространства. DOM-, Tab- и визуальный порядок совпадают; текст «Выйти», профиль и соседние элементы центрированы с допуском 2px.
- Переключатель пространства — control с фоном, иконкой и chevron, 240px на широком экране, на узком ограничен доступной шириной. Полное имя доступно, длинное сокращено визуально. Меню открывается под селектором: «Создать команду» первым фиксированным пунктом над разделителем, прокручиваются только пространства; keyboard/Escape/outside-click возвращают фокус. Геометрия и покадровая стабильность определены P0.2/UI.2. Отдельные декоративные двойные контуры не возвращать.
- Раздел: заголовок → одна строка вкладок/поиска/главного действия → контент. На tablet переносить фильтры и действия осмысленными группами. Не повторять одинаковый заголовок внутри вложенной карточки.
- Карточка интервью: название/статус → участники и контекст → дата/результат → действия. «Войти в комнату» — primary; копирование ссылки — secondary; UUID не становится подзаголовком. Завершённые результаты читабельны, «без оценки» не заменяется нулём.
- Библиотека: одна поверхность списка/сетки карточек; активная вкладка сохраняет фон/цвет при hover. Поиск и создание рядом с вкладками на широком экране. Архив задач/наборов снят по P1.3/P1.4; active/archive остаётся только у треков/вакансий. Формы и каталог выбора состава определены UI.2.
- Каталоги участников/HR/admin используют Table там, где строки сравнивают по колонкам. Библиотека и интервью сохраняют карточки/списки по существующему сценарию; не превращать весь продукт в таблицы.
- Создание/редактирование/импорт сущностей поверх списка — Modal, включая гостевое создание; живые код/условие/заметки/чат, поиск/фильтры и прямой профильный Switch сохраняют свои поверхности. Для стандартной формы width=560 px, короткого подтверждения=420 px, входа кандидата=440 px, сложной формы=800 px, редактора набора/программы до 960 px, всегда не шире viewport−32 px. Длинная форма прокручивается внутри; footer не закрывает поле/ошибку.
- Закрываемый Modal открывается с понятным заголовком, доступным именем каждого поля (без повторного видимого label названия в rename/create-team) и видимыми «Отмена»/основным действием. Исключения сохраняются: обязательный ввод имени перед входом в комнату не имеет Cancel/Escape/mask-close; диалог, запрещающий закрытие во время pending, сохраняет эту политику. Drawer не вводится как массовая замена уже принятых сценариев.
- Не менять данные по клику на контейнер там, где вложены rename/copy/delete; действия не всплывают в навигацию карточки.

- Шапки пространства/кабинета остаются видимыми при прокрутке; корневой horizontal clipping не создаёт новый scroll container. Hover интерактивных элементов шапки меняет фон, сохраняет текст/цвет/границу, focus отличается от hover; disabled не имитирует активность.
- Копирование показывает success/failure через context-bound Ant notification, не занимает место в карточке. Tag/badge компактный, не растягивается до высоты строки. Вкладки имеют внутренние отступы и активный индикатор без прилегающей заливки. Убрать декоративные вложенные контуры/акцентные боковые полосы, сохранив field borders и focus ring.
- Действия таблицы интервью закреплены справа; rename — карандаш у названия. Иконки/подписи разделены и выровнены. Карточки библиотеки сохраняют отступы и переносимые действия; metadata находится слева в информационном блоке по UI.2. У задач/наборов одна кнопка «Редактировать», без карандаша названия.
- Главная кнопка формы интервью имеет высоту 44px для доступности в коротком viewport/zoom. Room navigation actions имеют различимые поверхности. Select-popup внутри Modal привязан к слою диалога; Escape закрывает список раньше диалога.

Сохранить короткие пути входа: гость на landing заполняет существующую форму в Modal → создаёт комнату → видит рабочую область без обязательной регистрации; кандидат открывает ссылку → проходит текущую проверку доступа/ввод имени, если оно ещё требуется → попадает в комнату. Не добавлять onboarding или промежуточный экран. Пустое имя не принимается; альтернативный вход через аккаунт и возврат после login сохраняются. Вход в команду по team-invitation не смешивать со входом кандидата по room link.

### 5.2. Комната

- Верхняя панель, условие, шаги, чат, заметки, участники и результаты используют выбранную общую тему. Код/code blocks, Markdown и их панели следуют выбранной теме по UI.2; смена темы сохраняет документ, выделение и историю отмены.
- CodeMirror в dark: oneDark — основа категорий подсветки, но недостаточно контрастные оттенки корректируются. Editor background=`gray-900`, foreground=`gray-100`, gutter/comment/meta=`gray-400`, active-line=`gray-850`, selection=`#3e4451`. Нормативные коррекции syntax: coral `#f19ca3`, whiskey `#e1b386`, violet `#d7a0e8`, cyan `#84c8d1`, blue `#8cc4f4`; yellow/green oneDark сохраняются при прохождении контраста. Это отдельные editor tokens, а не изменения исходных primitives. Проверить text/active-line/selection, caret и remote overlays. Не применять UI primary как цвет всех syntax tokens. В light используется светлый набор editor/syntax tokens по общей теме; перечисленная dark-палитра не переносится на светлые поверхности.
- Отделять код тонкой границей и заголовком, не вкладывать редактор в несколько Card. Редактор выбранной темы не оправдывает старые dark-кнопки или неадаптированные диалоги.
- Название комнаты, текущая роль, опубликованный шаг и состояние кандидата доступны без открытия меню. Обычный статус «Соединение установлено» не возвращать; при проблеме показывать доступное предупреждение о reconnect.
- «Вернуться к списку интервью» отдельно от редакторских действий; возвращает в нужное пространство. Вид редактора выбирается явным переключателем «Код / Текст» по UI.2 R-25.
- Локальный выбор шага интервьюером не выглядит как публикация. Публикация — отдельное явное действие, доступное по действующим правам; обязательная программа защищена, решение кандидата редактируется по текущим правилам.
- При недостатке места существующая автоматика оставляет редактор и доступ к вспомогательным областям. Не добавлять видимые режимы Focus/Work/Overview или вкладку «Редактор».
- Минимум editor width в Work — 480 px полезной области по P2.1; если его нет, выбирать существующий Focus layout. Высота/минимумы панелей сохраняют безопасные границы.
- Цвета присутствия участников — отдельная палитра, стабильная на участника; не сводить всех к primary. Имя/метка дополняют цвет. Не менять генерацию identity, события awareness или курсорные координаты.

Состояния задачи в комнате:

| Состояние | Manager | Кандидат |
| --- | --- | --- |

### 5.3. Состояния и доступность

Каждая поверхность S01–S16 должна иметь перечисленные применимые состояния; `N/A` допустимо только с объяснением в evidence.

| Состояние | Ожидаемый интерфейс |
| --- | --- |
| Первая загрузка | Skeleton/Spin с сохранённой геометрией; не показывать ложный empty state или запрещённые ссылки |
| Повторная загрузка | Сохранить уже доступный контент и навигацию; локальный индикатор, без сброса формы/фокуса |
| Empty / no matches | Разные тексты; создать при наличии прав / сбросить фильтры; не обрезать иллюстрацию или текст рамкой |
| Pending mutation | Loading на конкретном действии, защита от двойного submit; остальные несвязанные действия по текущим правилам |
| Validation / server error | Ошибка рядом с полем и/или Alert формы; введённое остаётся; focus на первой ошибке после submit |
| Conflict / stale revision | Понятное сообщение и существующее безопасное обновление/повтор; не молча перезаписывать данные |
| Disabled / read-only / denied | Различимые состояния, причина доступна без hover; закрытые данные не рендерятся под disabled-оболочкой |
| Success | Локальное обновление + единый context-bound notification сверху по UI.2 R-24; без inline дубля и повторного сообщения при reload |
| Reconnect / terminal revoke | Предупреждение во время восстановления; при отзыве очистить защищённую область по существующему lifecycle, не оставлять её за overlay |

Клавиатура: label/name у каждого control, предсказуемый Tab, видимый focus. Один Escape закрывает только верхний слой, если он закрываемый; запрещённый Escape не должен закрывать нижний слой. После закрытия focus возвращается инициатору. Обязательный ввод имени и pending-dialog exceptions из §5.1 сохраняются. Tooltip не единственный источник имени. Скрытые панели не участвуют в Tab и accessibility tree; активный редактор сохраняет свой landmark/name. Не отключать глобально клавиши редактора из-за Dropdown/Modal.

Текст — минимум 4.5:1, крупный текст — 3:1; важные индикаторы/контуры взаимодействия — 3:1; цвет не единственный канал статуса. Минимальный самостоятельный click target — 24×24 CSS px, проектный default — 32×32. Основание: [WCAG contrast](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html), [target size](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html). Эти требования не означают автоматическую сертификацию всего приложения.

Без горизонтальной прокрутки всей оболочки при поддерживаемых размерах; допустима локальная прокрутка кода и действительно двумерных таблиц, при этом действия/заголовки доступны. При увеличении текста поля и кнопки могут расти выше базового min-height. [Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html) учитывать при проектировании; полное mobile/400% покрытие не объявлять выполненным этой desktop/tablet-миграцией.

| Card/Text/Title/Anchor | Card/Typography с семантическими HTML-тегами |
| Modal/подтверждение | Ant Modal или context-bound modal API |
| Menu/context actions | Dropdown/Menu |
| Alert/Loader/Skeleton | Alert/Spin/Skeleton |

| Table/Pagination | Ant Table/Pagination, прежняя server/client pagination семантика. В совместимом Pagination `total` — число страниц, `value` — текущая страница; адаптер согласует их с Ant current/total/pageSize. Для неуказанного pageSize используется 1; явный размер страницы сохраняется. Каталог участников и HR список показывают вторую страницу при превышении размера первой, возвращаются назад без потери фильтра. |

| Обычные UI icons | `@ant-design/icons` compatible v6; не смешивать случайно контуры/размеры |

Один доменный компонент может содержать несколько Ant primitives. Не создавать универсальные клоны Button/Input/Modal с полным дублированием API. Небольшие общие domain patterns (toolbar, empty state, confirmation) допустимы, когда имеют реальных потребителей и единое поведение.

Реестр разрешённых исключений:

| Исключение | Что остаётся | Что мигрирует |
| --- | --- | --- |
| CodeMirror/Yjs | EditorView, CRDT binding, selection/scroll/awareness | Tokens редактора, controls его toolbar |
| Markdown | marked, DOMPurify, highlight.js, CodeMirror authoring | Тема текста/code blocks, toolbar, меню |
| Постоянные панели/splitters | RoomContextPanels, layout math, useOwnerPanelResize, identity дочерних деревьев | Цвета/ручки/доступность управления; **не заменять Splitter в этой доработке** |

Новый частный control или оставшийся Tabler icon требует строки в реестре: файл, потребитель, почему Ant не подходит, как проверена доступность. «Так быстрее» не является основанием. Доменная визуализация не обязана быть Ant Card.

## 7. Технический контракт миграции

- Используется стабильная Ant Design **6.x не ниже 6.3.2**, точная версия зафиксирована lockfile. При следующем обновлении сверить minor с [официальным migration guide](https://ant.design/docs/react/migration-v6/); ради документарной правки обновление не требуется. `componentSize=medium` сверить с типами выбранной версии. React 18 сохраняется. Не добавлять React 19 patch, React upgrade или новый сборщик без отдельной необходимости.
- Корень: существующие StrictMode/Redux provider → ConfigProvider(theme, русская locale) → Ant `App` → BrowserRouter/текущий application tree. Ant `App` сохраняет реальный стандартный `div` для CSS-variable class, `component={false}` запрещён. Импорт Ant `App` именовать отдельно от собственного `App`. Сохранить существующие auth/analytics/invitation bootstraps и lazy boundaries. Основание: [Ant App context](https://ant.design/components/app/).
- Все message/notification/modal вызовы получают theme/context через `App.useApp` или документированный context holder; не использовать статические вызовы, теряющие контекст.
- Использовать штатный CSS-variable режим v6, `defaultAlgorithm`/`darkAlgorithm` и overrides выбранного режима; сохранить hash isolation. Не вводить zero-runtime extraction, CSS-in-JS замену, глобальное отключение hash или `theme: undefined` как переключатель. Не создавать отдельные conflicting ConfigProvider на страницах. Theme object меняется без `key={mode}` или замены provider tree.
- Для точного совпадения CSS и Ant недостаточно передать seed primary в darkAlgorithm: он пересчитывает палитру. Использовать тонкий чистый adapter официального алгоритма, затем накладывать нормативные MapToken-цвета режима; AliasToken overrides передавать через theme.token. Не включать повторный component algorithm поверх фиксированных ролей. Сверять `getDesignToken(config)` и computed controls с независимыми значениями §4 для обоих режимов. Основания: [theme algorithms](https://ant.design/docs/react/customize-theme/), [dark algorithm v6.6.5](https://github.com/ant-design/ant-design/blob/6.6.5/components/theme/themes/dark/index.ts), [alias overrides](https://github.com/ant-design/ant-design/blob/6.6.5/components/theme/util/alias.ts).
- Overlay blur явно отключён поддерживаемым API выбранной v6 minor; сохраняется однотонная mask из §4. Не зависеть от изменения default blur между версиями и не добавлять blur-фильтры через CSS.
- `ru_RU` применяется к стандартным UI-строкам; при использовании Ant date controls также подключить русскую locale Day.js по [DatePicker API](https://ant.design/components/date-picker/). Язык кода/настройки задачи не является locale. Формат дат и диапазоны HR сохраняют действующую московскую семантику; замена поля на date control не меняет payload/timezone.
- Ant reset подключён один раз согласованно с app reset. Legacy MantineProvider/reset не возвращать: миграция стандартных controls выполнена, светлый body не должен наследовать старую dark-тему.
- CSS Modules отвечают за layout и специализированный контент. Внешний вид Ant менять token/component token API, затем документированными semantic `classNames/styles`. Не привязываться к сгенерированным hash class names, DOM-структуре внутренностей или глобальным `.ant-*`/`.mantine-*` хакам. Временные исключения не оставлять после завершения затронутой миграции.
- Слои: обычный контент → sticky header → dropdown/tooltip → modal mask/content → popup внутри modal → notification. Использовать Ant stacking context и token `zIndexPopupBase`; проверить вложенные popups и LegacyDomainNotice. Старые 1500/3000/9000 не переносить автоматически.
- Существующий `useEscapeLayer` и Ant keyboard handling должны иметь одного владельца события для активного слоя. Сначала регрессия вложенных Select/Modal и редакторских меню, затем замена обработчика; не оставлять двойное закрытие.
- Формы: сохранить controlled state, payload и существующую цепочку запросов без дублей. Личное CreateInterview может создавать комнату и затем отдельно сохранять metadata; metadata-only retry не создаёт новую комнату. `Input.onChange(event)` и `Select.onChange(value)` не взаимозаменяемы. `Form` разрешён для layout/validation, но не создавать параллельную копию RTK/domain state. Submit/Enter/IME/повтор после ошибки проходят реальный путь.
- Lifetime: без случайных новых keys, destroy-on-hidden, reparent/remount editor, chat или notes. Перенос между панелями не завершает SSE и не создаёт новую Yjs session. Политика черновика при закрытии формы сохраняется по текущему сценарию; визуальная замена её не меняет.
- Не менять endpoint definitions, auth/access guards, feature flag defaults, storage форматы и аналитические события. Не добавлять theme/draft persistence с invitation token/link, idempotency key или private candidate data. Существующий целевой invitation-auth lifecycle сохраняется без расширения его использования.
- Route lazy loading остаётся; не подтягивать CodeMirror/все иконки в публичный entry только ради общей темы. Импорты icons по используемым компонентам. Зафиксировать размеры production chunks до/после; рост initial JS/CSS >10% требует объяснения и решения до приёмки, это проектный gate, не гарантия от библиотеки.
- Финал: в `frontend/src` нет Mantine imports, styles/provider, самодельных стандартных controls вне реестра; в runtime dependencies нет Mantine core/hooks. Удалить Tabler, если больше нет зарегистрированных потребителей. Специализированные зависимости сохраняются.

## 9. Критерии приёмки

- **AC01 — единая система двух тем.** На S01–S16 цвета соответствуют выбранному режиму, шрифтовые роли/высоты/радиусы одинаковы; portals и вложенные popups сразу наследуют переключение. Проверка theme contract + screenshots light/dark.
- **AC02 — готовый token contract.** Все используемые tokens определены, числа конечны, импорт не читает DOM, типы проходят без подавлений; один источник значений; нет чёрных/прозрачных fallback из отсутствующих переменных.
- **AC03 — Ant-first.** Все стандартные controls используют mapping §6; исключения перечислены. Mantine удалён после покрытия потребителей, антовские иконки консистентны.
- **AC04 — навигация.** Во всей матрице header соблюдает overflow и разрешённый tablet перенос по P0.2/UI.2, logout виден, длинные имена не перекрывают действия, burger/focus/Escape/back/forward/team context работают без лишнего запроса/мигания.
- **AC05 — формы и данные.** Один пользовательский intent без дублирующих mutations; существующие многошаговые запросы и metadata-only retry сохранены. Значения/ошибки/повтор/конфликт корректны, обязательность полей и политика draft неизменны, destructive требует существующего подтверждения.
- **AC06 — библиотека и интервью.** Реальные copy/import/edit/delete, порядок, optional tasks, programme, «Мои интервью», rename и candidate link проходят в личном/командном контексте. Archive только у треков/вакансий, существующие snapshots задач/наборов неизменны.
- **AC07 — комната.** 20 переходов resize/panel/reflow/theme при неизменных mode/step/language сохраняют живой editor/Yjs identity, код, selection, оба scroll, выбранный шаг, private draft, chat draft/read position; нет layout/theme mutations в room API. Отдельно смена code↔Markdown восстанавливает код и публикацию режима по текущей модели: она может штатно демонтировать editor и отправлять domain mutation, не требует нового lifecycle ради визуальной миграции.
- **AC08 — роли и realtime.** Кандидат не видит manager UI; локальный шаг не публикуется сам; reconnect/stale response/revoke и ограничения жизненного цикла комнаты не раскрывают данные и не восстанавливают действие/роль.
- **AC09 — доступность.** Контраст обеих тем, targets, visible focus, screen reader names, keyboard, top-layer Escape, reduced motion и zoom проверены; обязательный name-entry не закрывается Cancel/Escape/mask, pending-dialog сохраняет запрет закрытия; known blockers закрыты.
- **AC10 — эксплуатация.** Typecheck/build и целевые тесты пройдены в изоляции; lazy recovery/feature-off/загрузка шрифта не ломаются, нет новых theme/deprecation/runtime warnings; chunk delta объяснена.
- **AC11 — визуальная завершённость.** Скриншоты всех S-поверхностей, модалей и error/empty/pending состояний используют синтетические данные; нет элементов от противоположной темы, двойных рамок и обрезанных controls.
- **AC12 — честный handoff.** Выполненный scope связан с AC и реальными результатами/evidence, ограничения указаны; UI.1 и SPEC.md обновлены. Техническая готовность и продуктовая приёмка записаны отдельно.
- **AC13 — переключение.** Fresh/saved/invalid/blocked storage, deep-link reload, login/logout, cross-tab sync и slow load выполняют §4.6. Нет вспышки противоположной темы; pressed-state соответствует режиму. Открытые portals и pending формы сохраняются. В отдельном тесте 20 theme toggles не пересоздают EditorView/Yjs/SSE и не теряют код, selection, scroll, notes/chat draft.

Backend-код не меняется. Для сценариев permissions/persistence/concurrency использовать относящиеся к затронутому UI существующие PostgreSQL integrations, если затронута привязка запроса/роль/payload. Не требовать зелёного полного исторического H2 suite: ограничения зафиксированы в P6; новые ошибки затронутого scope всё равно блокируют его приёмку.

### 11.2. Визуальная и размерная матрица

Это объём итоговой приёмки всей миграции. Для последующей небольшой правки
выбирать затронутые состояния/размеры по риску; полный повтор нужен только
при изменении общих зависимостей или неразрешённой регрессии.

Сохранить шесть существующих viewport: **768×1024, 1024×600, 1024×768, 1280×720, 1366×768, 1440×900** и zoom-equivalent **100/125/150/200%**. Существующий harness моделирует zoom изменением viewport; это не native browser zoom. В evidence различать симуляцию и ручную проверку настоящего zoom, если она выполнена.

- На всей матрице проверить shell/navigation, room geometry и доступ к действиям в коротком viewport.
- Для остальных S-поверхностей: минимум 1366×768, 768×1024, 1024×600; для каждого типа сложной формы — также 200% equivalent, отсутствие clipping/focus trap.
- Весь указанный охват выполняется в **light и dark**. Для controls/portals отдельно показать default/hover/focus/active/selected/disabled/loading/error; для комнаты — оба UI-режима с кодом и Markdown, включая смену темы во время ввода.
- Эталонные screenshots: landing/login, personal/team list, обе библиотеки, create interview, tracks/programme, members/invite/settings, HR/details, room interviewer/candidate/Markdown/reconnect/finished, admin/feedback.
- Контент: длинные кириллические имена, длинная задача/код, пустые коллекции, большие списки, ошибки, pending, denied. Только синтетические данные; ссылки/секреты маскировать в evidence.
- Скриншоты соответствуют фактически проверяемым S/AC и реальным состояниям; не объявлять план screenshots уже выполненным доказательством.

### 11.3. Приёмка и независимый обзор

Для незавершённой приёмки всей миграции исполнитель передаёт файлы, S/AC, результаты, скриншоты и ограничения; независимый UX обзор проверяет иерархию/состояния/геометрию, технический — theme/provider contract и регрессии. Последующая обычная правка использует объём проверки по риску из specs/README.md, без обязательной цепочки ролей. Существенные изменения lifetime/auth/защищённых данных/realtime требуют независимого scoped security/reliability review; это не разрешение расширять backend scope.

Не записывать «всё готово» при оставшихся Mantine surfaces, отсутствующей candidate-проверке, неучтённых exceptions или проваленном AC. После технического gate отдельно провести продуктовый просмотр пользователем. Новая UI-миграция не изменяет статусы готовности прежних бизнес-фич.

## 12. Текущее состояние и доказательства

По журналу 23–24.09.2026 S01–S16 переведены на Ant Design 6.6.5 и
@ant-design/icons 6.3.4, Mantine/Tabler удалены. Подключены общий manifest,
bootstrap/provider, обе темы, поля/таблицы/навигация/диалоги и room chrome.
CodeMirror и специализированные controls сохраняются по реестру §6.
Действующие продуктовые поправки журнала включены в §4–9 и UI.2.

Техническая приёмка **частичная**: целевые theme/room/library/navigation,
typecheck/build и проверка документа имели положительные результаты в журнале,
но полный screenshot/viewport охват §11.2, все portals/states и общий независимый
UX/technical gate там не подтверждены. В раннем прогоне 3 TEAM E2E пропущены
при выключенном флаге; последующие целевые TEAM-прогоны не заменяют всю матрицу.
`e2e:room-context-panels` содержит снятые Focus/Work/Overview ожидания, требование
не настроенного lifecycle log и запрет действующего manager workspace awareness;
его нужно привести к P2.1, без возврата удалённых controls. Room smoke и отдельные
ролевые/panel/export проверки не доказывают зелёный полный suite.
Сборка ранее имела предупреждения о размере chunks/assets. Полный продуктовый
просмотр/приёмка дизайна остаётся отдельным шагом; UI.2 хранит последующие целевые
результаты и замечания, не объявляя весь UI.1 принятым.

Исходные вложения сохранены в references и не подключены в production.
[Историческая редакция и подробный журнал](../references/history/ui-1-antd-v6-design-system-2026-10-02.md)
содержат прежний inventory, T01–T18, команды, дату, результат и ограничения.
[UI.2](ui-2-usability-theme-polish.md#состояние-и-доказательства) ведёт ссылки на
последующие проверки по сценарию. Прежний PASS не считать новым запуском.
Нормализация 2026-10-02 проверяет документы и ссылки; приложение не запускается.
