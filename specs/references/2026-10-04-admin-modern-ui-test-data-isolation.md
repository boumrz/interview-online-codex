## Локальная очистка

Выполнена по явному запросу пользователя только в локальной
`interview_online/public`. На стенде данные не удалялись.
Из 8483 аккаунтов удалены 8471 тестовых; сохранены 12 обычных аккаунтов:
`boumrz`, `boumrz1`, `boumrz111`, `boumrz123`, `boumrz222`, `boumrz1112`,
`111`, `123`, `test`, `roman_qa`, `12312`, `123133213`.
Два последних сохранены ради существующих связей и истории — исходный запрос
допускал около десяти аккаунтов.

Перед удалением создана private PostgreSQL custom backup (5.6 MB, права 0600).
Её восстановление проверено в отдельной схеме scratch DB. Подготовленный
план сначала выполнен на этой копии, затем с ROLLBACK в основной базе и
лишь после независимого approve — с COMMIT. Точный loopback/database/schema,
исходные количества, сохранение boumrz и всех FK проверялись внутри операции.

Удалены связанные тестовые объекты: 1727 команд, 3490 комнат, 10320 личных задач
и их зависимости. Сохранены 6 команд, 42 комнаты оставленных владельцев,
19 личных задач и их связи/история. 1412 комнат без владельца сохранены;
итого комнат после очистки — 1454. Fingerprints содержимого всех сохраняемых
строк в 33 таблицах совпали до/после. Все 59 FK валидны; 15 проверок пересечения
мягких ссылок — 0; agent-таблицы с `created_by` пусты.
Условия `AdminUserService`, включая запрет удаления связанных с командой
аккаунтов из приложения, сохранены. Это отдельная операторская очистка fixtures.

Backup и приватные SQL/агрегированные отчёты находятся в ignored
`.run/local-account-cleanup/`. Rehearsal-схема и лишние plaintext-копии дампа
удалены, custom backup сохранена. Секреты и частные строки не включены в отчёт.

## Предотвращение накопления

P6 R-08/AC-08. Причина: прямые E2E самостоятельно регистрировали fixtures по
default URL основного API; package scripts запускали их без изоляции.
Теперь package команды используют общий runner с собственной backend copy,
временной PostgreSQL-схемой и свободными портами. Прямые E2E защищены общим
ранним import. До fixtures проверяются идентичность API и его web proxy по
read-only test-only endpoint с фактической database/schema.
Обычные main URL, неверные metadata/proxy, удалённый PostgreSQL и legacy
переопределения отвергаются. Endpoint не включён в production runtime.
Своё окружение удаляется после успеха и ошибки, включая дочерние процессы,
чей родитель уже завершился.
