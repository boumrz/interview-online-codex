# Участники в редакторе интервью — 05.10.2026

Запрос: убрать повторяющий подпись заголовок нанимающих и сделать командный
редактор таким же, как создание, с выбором других интервьюеров.
Договор: UI.2 R-16/R-30/AC-24, P1.5 R-14/AC-05; права нанимающих остаются P2.3.

## Результат

- TEAM создание и редактор содержат раздел «Участники» с двумя полями:
  «Другие интервьюеры (необязательно)» и «Внешний нанимающий (необязательно)».
  Отдельного заголовка «Внешние нанимающие» нет.
- PERSONAL создание и редактор содержат поле «Нанимающий» без дублирующего
  заголовка. Существующая разделительная линия и отступы сохранены.
  Командный каталог интервьюеров/треки/вакансии не запрашиваются в PERSONAL.
- Выбор командных интервьюеров сохраняется по «Сохранить» вместе с названием,
  сведениями кандидата и контекстом. Отмена ничего в выбранном составе не меняет.
  Нанимающие сохраняют отдельные подтверждённые действия добавления/снятия.
- GET TEAM details возвращает `ownerUserId` и `interviewerIds`. Optional список
  в PATCH задаёт выбранный состав; отсутствие поля сохраняет старый состав,
  явный `[]` убирает выбранных обычных ACTIVE интервьюеров. JSON null/неверные
  типы отклоняются. Повторы IDs канонизируются без дублирующих назначений.
- Сервер использует общий revision/CAS и team→room locks, затем блокирует
  выбранные memberships в стабильном порядке и перепроверяет актуальную ACTIVE
  принадлежность. До изменения данных проверяется весь состав. Owner, hiring
  assignments, кандидаты, внешние/гостевые и неактивные исторические назначения
  сохраняются. Снятие выбора не меняет общий доступ ACTIVE сотрудников команды.
- Сеть/409 сохраняют черновик; `TEAM_MEMBER_NOT_FOUND` при снятии сотрудника
  допускает исправление состава без потери названия/metadata. Отказ доступа к
  самой комнате очищает приватные поля, поздний ответ не восстанавливает их.
  Справочник участников загружается по всем страницам; выбранный человек за
  пределами первой страницы не теряется, внутренние IDs не показываются.
  Отсутствующая в свежем справочнике выбранная цель имеет нейтральную подпись.
- Задачи/программа/контекст/owner credentials не мигрируют. Google/VK выключены.

## Проверки

Все фикстуры использовали отдельную PostgreSQL 16 схему и scratch database,
отдельные HTTP порты и браузерные профили; пользовательская БД не изменялась.

- Backend RED: три сценария подтвердили отсутствующее поведение GET/PATCH.
  Четвёртый lock-wait сценарий не достиг room lock из-за старого strict parser;
  он не считается отдельным подтверждённым поведенческим RED.
- Browser RED: TEAM раздел/интервьюеры и PERSONAL повторяющийся заголовок —
  2 подтверждённых отказа; отдельный RED исправимого target404 — 1 отказ.
  Первые ошибки тестовых locator helpers исправлены и не считаются RED.
- PostgreSQL: **14 уникальных сценариев PASS**, failures/errors/skips = 0:
  четыре новых сценария состава и десять прежних metadata/context/CAS/прав.
  Проверены добавление/смена/очистка, self-selection ACTIVE редактора,
  сохранность owner/HR/candidate/external/former rows, отсутствие частичного
  сохранения, typed bodies, legacy PATCH, stale revision и смена состояния
  выбранной цели во время ожидания room lock.
- Browser: **18 уникальных сценариев PASS**, 0 failures/skips: полный TEAM
  редактор 14 и PERSONAL hiring regression 4. Проверены заголовки/разделители,
  add/change/clear/reload, owner/HR/tasks/context, отмена, сеть/реальный 409,
  исправление typed и реального target404 после удаления коллеги, все страницы
  каталога, self-selection редактора, 401 и поздний ответ. Предыдущие 13/14
  исправляли только ошибочное ожидание теста owner-only в карточке: сохранённый
  внешний HR также закономерно остаётся в именах интервьюеров. Этот повтор
  не прибавляется к количеству; итоговый полный запуск 18/18 — PASS.
- TypeScript, frontend сборка изолированного runner и backend package — PASS.
  338 production source fingerprints неизменны в финальном браузерном прогоне.
- Независимый scoped security/reliability review — **approve / pass / pass**,
  без блокирующих замечаний; независимо сверены XML14, browser18 и fingerprints.
  Сохранность различных назначений, свежие locks/CAS и private recovery проверены.
- Полный локальный restart — PASS: frontend 5173 и backend 8080 готовы с
  прежними настройками и стабильными ключами. Read-only smoke PASS: health,
  защищённый API, форма входа без браузерных ошибок, Google/VK скрыты.
