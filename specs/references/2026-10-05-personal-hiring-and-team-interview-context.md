# Нанимающие PERSONAL и контекст редактора TEAM — 05.10.2026

Текущий запрос пользователя уточняет прежний scope: личное интервью может
иметь зарегистрированного нанимающего, выбранного по нику. Термин «внешний»
и поясняющий текст в PERSONAL не нужны. Трек и вакансия остаются командными
сущностями и должны выбираться также при редактировании TEAM интервью.

Актуальный договор: UI.2 R-11/R-16/R-18/R-30/AC-24, P2.3 R-11/AC-10,
P3.4, P1.5 R-14/AC-05 и P1.2 R-01/AC-01. Этот результат заменяет прежний
запрет PERSONAL HR операций в отчёте personal-team-scope-and-copy; прежние
результаты тем, кратких текстов и terminal 404/410 сохраняют своё назначение.

## Реализация и границы

- PERSONAL создание, общий редактор списка и сведения комнаты содержат
  «Нанимающий»/«Нанимающие»: точный поиск по нику, подтверждённое имя,
  добавление и снятие назначения. Нет UUID/ID или слова «внешний» в этой UI.
  Новые поля трека/вакансии и запросы командных справочников в PERSONAL не добавлены.
- Используется прежняя eligibility: зарегистрированный аккаунт с включённой
  функцией «Нанимающий» (`isHr=true`). Обычный или недоступный аккаунт получает
  такой же отказ поиска, как несуществующий. Набора зарегистрированных людей
  UI не запрашивает — только конкретный ник.
- При создании выбранные люди отправляются каноническим списком, дубли удаляются.
  Сервер проверяет актуальный профиль под user locks; ошибка цели не создаёт
  частичную комнату или назначения. Pending поиск исключает неподтверждённый
  submit; очистка/закрытие/смена аккаунта отменяют lookup. Сведения кандидата и
  восстановление частично сохранённых данных работают по прежнему контракту.
- Назначение даёт актуальную interviewer authority и запись в личном кабинете;
  снятие роли/отзыв/смена аккаунта закрывают private формы, поздний ответ не
  восстанавливает доступ. Обычный PERSONAL guest с hiring-флагом остаётся обычным
  интервьюером до явного назначения. Автоматический tracking владельца не
  возвращён: его кабинет выводит собственные интервью напрямую.
- Manager HTTP API применяет права авторизованного аккаунта. Аккаунт не может
  заимствовать чужой event token; анонимный запрос использует только текущий
  anonymous proof с проверкой роли/комнаты/scope/revoke. TEAM anonymous HTTP
  metadata/HR границы не расширены. Tracking повторно проверяет включённую
  функцию после ожидания room lock; смена профиля во время ожидания не создаёт
  запрещённую запись. Исторические данные и схема не мигрировали.
- TEAM редактор добавляет, меняет и снимает трек/вакансию. Смена трека очищает
  прежнюю вакансию. GET содержит сохранённые IDs/названия как внутренний контракт;
  PATCH поддерживает необязательный `context: {trackId, vacancyId}`. Отсутствие
  `context` сохраняет связи старых клиентов, явные null очищают их.
- Контекст, название и сведения сохраняются одной общей revision. Чужая команда,
  несовпадение трека/вакансии, новый архивный reference, неподходящие JSON типы
  или конфликт не дают частичной записи. Неизменённый исторический архивный
  контекст сохраняется и виден в редакторе. Задачи и опубликованный snapshot
  программы не пересоздаются. Ошибка сети/409 сохраняет контекстный черновик,
  актуализация загружает новые сведения.

Google/VK остаются выключенными согласно AUTH.1.

## Проверки

Запуски используют отдельные PostgreSQL 16 схемы, порты и браузерные профили;
тестовые записи в пользовательскую локальную БД не добавляются.

- RED PERSONAL: 8 из 15 PostgreSQL сценариев не получали новое поведение;
  два browser сценария не находили поле создания и действие комнаты.
- Дополнительный RED tracking: 1 из 43 PostgreSQL проверок обнаружила stale
  `isHr` после ожидания room lock. Исправление подтверждено свежими lock-wait
  сценариями. Ошибки настройки/компиляции не считаются поведенческим RED.
- PERSONAL backend: **145 уникальных проверок в 14 XML — PASS**. Широкий прогон
  дал 140 PASS и пять устаревших ожиданий прежнего blanket запрета. Исправлены
  только тесты по новому договору; свежий повтор трёх классов, 44 PASS, заменяет
  эти XML и не прибавляется к уникальному количеству. Проверены права, profile
  races, guest proof, canonical creation, отзыв/regrant, кабинет, архив и экспорт.
- TEAM context: **10 PostgreSQL — PASS**: добавить/сменить/очистить, старый PATCH
  без контекста, CAS, атомарный отказ чужих/архивных/несовместимых ссылок, строгие
  JSON типы, сохранение непустых задач и реального опубликованного snapshot.
  Класс не входит в предыдущие 145. Независимый разбор XML: **155 уникальных
  cases**, failures/errors/skips = 0.
- PERSONAL и зависимая регрессия: **29 browser — PASS**: новые flows 4,
  PERSONAL/TEAM scope 9, cards/CAS/late/revoke 7 и выбранные HR regression 9.
- TEAM редактор: **7 browser — PASS**, включая новый контекст/network/409,
  сохранение архивных значений, retry справочника и прежние title/metadata/HR/
  account/revoke/creation recovery сценарии. Повтор прежних 6 не суммируется.
- Дополнительная подготовка и отмена поиска: **3 browser — PASS**. Личный
  подбор без командных полей, командный поиск/редактор в обеих темах и на 768px,
  отмена pending lookup при закрытии. Всего **39 уникальных browser — PASS**.
- TypeScript и backend package — PASS. Независимый scoped security/reliability
  review — **approve**, без блокирующих замечаний: актуальные права после locks,
  гостевые proofs, атомарность и context CAS. Обзор сверил 155 PostgreSQL и
  36 основных browser; три дополнительные проверки подготовки затем прошли
  без изменений production source.
- Полный локальный restart — PASS: backend 8080 и frontend 5173 готовы.
  Сохранены существующие конфигурация и стабильные ключи. Read-only smoke —
  PASS: health, защищённый API, форма входа без ошибок браузера; Google/VK скрыты.
  Пользовательская БД не использовалась для тестовых фикстур.
