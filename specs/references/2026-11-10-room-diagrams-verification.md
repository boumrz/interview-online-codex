# Проверка P2.4: схемы в комнате

Дата: 10 ноября 2026 года.
Контракт: [P2.4](../features/p2-4-room-diagrams.md).
Результат: первый выпуск реализован и технически проверен; продуктовый просмотр
ожидается. `FEATURE_ROOM_DIAGRAMS_ENABLED=false` остаётся значением по умолчанию.
Пользовательское приложение и его рабочие environment-файлы не менялись,
процессы пользователя не запускались, не останавливались и не перезапускались.

## Что реализовано

- Один общий документ комнаты; «Схема» расширяет существующий общий режим
  Code/Markdown с подтверждением управляющего. Содержимое не привязано к шагу.
- draw.io 32.6.10 обслуживается существующим frontend. В runtime ресурсы локальны;
  отдельного сервиса, платформы или платной интеграции нет. Поставка фиксирована
  версией и SHA-256; upstream JS не проходит повторную минификацию Rspack.
- Изменения принимаются по точной базовой последовательности; canonical XML,
  журнал восстановления и квитанция операции записываются атомарно в PostgreSQL.
  SSE публикуется после завершения транзакции. Устаревшая полная копия не заменяет
  более новый документ; повторы сохраняют идентичность намерения.
- Видимый редактор сохраняет локальную историю. Скрытый экземпляр того же
  статического редактора собирает точный принимаемый снимок без будущих правок
  очереди. Порядок объектов согласуется с подтверждённым XML; проверяется native
  checksum, включая его фактическое представление signed integer.
- Новый stream не отправляет diagram-запросы до текущего state_sync capability.
  Поздний отказ старого capability сохраняет очередь до восстановления свежего.
- Finished кандидат получает просмотр; управляющий может продолжить разрешённую
  работу. Для finished/frozen читателя доступен локальный просмотр схемы также
  при общем Code/Markdown, без изменения режима остальных участников.
- Экспорт `.drawio`, PNG и SVG строится из подтверждённого документа. При
  постоянном отказе валидации несохранённое остаётся до явного подтверждения
  возврата к сохранённой версии.

независимого чтения долговременного состояния, а не поддержка realtime-кластера.

## Воспроизведение

Из `backend`:

```sh
JAVA_HOME=/Library/Java/JavaVirtualMachines/temurin-17.jdk/Contents/Home \
mvn -q -Dtest=RoomDiagramIntegrationTest,RoomDiagramDisabledIntegrationTest,RoomEditorModeIntegrationTest test
```

Из `frontend`:

```sh
npm run typecheck
node --experimental-strip-types --test tests/unit/diagramProtocol.test.ts tests/unit/diagramBridge.test.ts tests/unit/diagramRequestPolicy.test.ts
npm run prepare:drawio
node --test tests/contract/drawio-assets.test.mjs tests/contract/drawio-protocol-browser.test.mjs
FEATURE_ROOM_DIAGRAMS_ENABLED=true E2E_SECOND_BACKEND_PORT=47888 E2E_PRODUCTION=true \
node tests/e2e/run-isolated.mjs tests/e2e/interview/e2e-room-diagrams.mjs
FEATURE_ROOM_DIAGRAMS_ENABLED=false \
node tests/e2e/run-isolated.mjs tests/e2e/interview/e2e-room-shared-mode.mjs
```

Runner требует безопасную локальную PostgreSQL 16, создаёт собственную схему
и процессы на свободных портах, затем удаляет их. Второй порт должен быть свободен.
Работающий пользовательский стенд не используется. Все browser fixtures —
синтетические интервью. Содержимое схем и credentials не выводятся в отчёт.

## Независимый обзор

Security: **pass**. Reliability: **pass with notes**; подтверждённых блокирующих
замечаний после исправлений не осталось. Проверяющий самостоятельно прогнал
13 native/assets и 16 unit, проверил PostgreSQL-отчёты и сквозные журналы.

Исправлены с подтверждёнными RED: небезопасные native patch/page payloads,
compressed stencil bombs, чрезмерный recovery batch, нестабильные дубли ID,
старые capability-отказы, компактированные ACK и native checksum type.
Обычные корректные native patches, группы и свободные штрихи сохранены.

## Границы и оставшийся просмотр

- Одна бесконечная страница на интервью. Отдельные схемы задач, templates,
  приватные эталоны, AI и пользовательский asset upload остаются вне выпуска.
- Настройки вида страницы локальны; структурные фигуры и штрихи сохраняются
  для всех. Встроенный редактор получает текущую тему при первом открытии;
  смена темы оболочки не пересоздаёт iframe и его Undo.
- Пределы: XML 2 MB, patch 250 KB, 5 000 элементов; native stencil распаковывается
  с пределом 256 KiB на рисунок и 2 MB суммарно. Incremental recovery — последние
  128 операций и бюджет 4 MB; более старый/большой запрос получает полный снимок.
- Существующая realtime-топология требует закрепления комнаты за одним хостом
  либо отдельного межпроцессного fanout из общей очереди SPEC. Новый сервис не добавлен.
- Phone/mobile и полный нагрузочный/длительный soak не запускались. Целевые
  проверки покрывают Chromium desktop, реальные light/dark состояния и
  существующую геометрию Code/Markdown. Остальная desktop/tablet browser matrix
  требует обычного продуктового просмотра.
- В изолированных журналах есть существующие Broken pipe/completed SSE emitter
  сообщения при закрытии браузерных fixtures; целевые проверки завершились без
  отказов. Это не скрывалось и не исправлялось несвязанным realtime-рефакторингом.
- Продуктовый просмотр и включение функции в рабочем окружении ещё не выполнены.

## Расширение области проектирования

После замечания о маленьком холсте добавлены два независимых локальных действия:
«Развернуть схему» на всё окно для всех ролей, включая readonly, и скрытие боковой
панели комнаты с возвратом прежней вкладки и ширины. Существующее сворачивание
условия остаётся отдельным действием. Контракт: P2.4 R-12 / AC-11, P0.3 R-06 / AC-06.

Разворачивание меняет CSS того же экземпляра редактора; iframe, Undo, очередь,
выделение и совместная работа сохраняются. Фон недоступен для фокуса, диалог
возврата к сохранённой версии работает внутри развёрнутой панели. Общий счётчик
блокировок `inert` согласует скрытую область и развёрнутый редактор: изменение
ширины через порог раскладки не открывает фон и не разблокирует скрытую панель
после возврата. Escape остаётся у native редактора, возврат доступен кнопкой.
