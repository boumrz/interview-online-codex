# История, не действующие требования

Снимок перед актуализацией итогов проверки 2026-10-02.

### P2.1 Layout режимы комнаты

Цель: комната корректно работает в режимах Focus / Work / Overview.

Текущее решение (2026-09-23): видимых режимов Focus/Work/Overview нет; раскладка выбирается автоматически по ширине, а кнопка «Только markdown» меняет основной редактор у интервьюера и кандидата. Ниже сохранены технические результаты предыдущей итерации, в том числе проверки внутренней адаптивной раскладки.

Уже сделано:

- переключатели Focus / Work / Overview и auto-mode по фактической геометрии
  рабочей области уже реализованы в `RoomContextPanels`;
- вкладка «Редактор» не возвращена: редактор остаётся прямым region;
- в Focus вспомогательные области снова доступны через aux-tabs без editor-tab,
  а возврат в редактор сделан отдельным действием «К редактору»;
- локальные splitters работают клавиатурой/мышью и не отправляют room
  mutations/split/resize события;
- кандидат не видит manager surfaces, личные заметки и publish action;
- editor/Yjs session не remount-ится при 20 reflow/panel transitions, сохраняет
  code, selection, vertical/horizontal scroll, drafts, chat read position и
  room session id без synthetic form mutations;
- временное отсутствие scroll overflow не стирает выбранную пользователем
  позицию редактора; при возвращении узкой панели она восстанавливается;
- в Focus с открытым редактором ни одна скрытая вспомогательная вкладка не
  помечается как выбранная;
- поздняя загрузка профиля не очищает уже введённый черновик личной заметки.
- проверка:
  - unit `roomContextPanelLayout.test.ts` — зелёный `3/3`;
  - frontend isolated E2E:
    `candidate receives no manager surfaces`,
    `focus mode keeps auxiliary surfaces reachable`,
    `remediation: editor is a direct Focus region...` — зелёный `3/3`;
  - совместный frontend E2E прогон Focus, 20 переходов, desktop/tablet zoom и
    usable geometry — зелёный `4/4`;
  - полный E2E набор поверх изолированной PostgreSQL схемы с включённой
    диагностикой SSE — зелёный `19/19`;
  - frontend `npm run typecheck` — зелёный.

Итоговая проверка:

- полная матрица desktop/tablet и zoom 100/125/150/200% прошла на чистом PostgreSQL runtime;
- тест корректно завершает старое посещение комнаты перед повторным входом, чтобы сервер освободил SSE-сессию;
- минимальная ширина редактора в режиме Work увеличена до 480 px внутри редактора; при нехватке полезной ширины интерфейс выбирает Focus;
- unit проверки границ splitter `3/3` прошли после изменения.

Acceptance:

- кандидат не видит внутренние панели и не может публиковать шаг;
- интервьюер может локально выбирать шаг без публикации кандидату;
- публикация шага — отдельное явное действие;
- draft/selection/scroll сохраняются при 20 переключениях/resize.

## Надёжность подключения комнаты

- **R-01. Граница отправки:** проверка доступа и регистрация подключения/lease
  выполняются в короткой транзакции. Первоначальная отправка SSE и завершение
  заменённого подключения происходят после освобождения транзакции, блокировки
  комнаты и соединения базы; медленный клиент не удерживает ресурсы записи.
  При параллельном reconnect одного sessionId позднее завершение старого
  подключения не закрывает новое.
- **AC-01:** остановка непосредственно перед первоначальной отправкой SSE →
  нет активной транзакции, число занятых соединений базы равно исходному;
  повторный вход той же сессии сохраняет единственное новое подключение.
  Проверка: `RoomStreamAdmissionSendBoundaryIntegrationTest` и
  `RealtimeConnectionLifecycleIntegrationTest`.
- **R-02. Непрерывный ввод Markdown:** изменения владельца/интервьюера отправляются
  и во время непрерывного ввода, а не только после паузы. Неподтверждённый текст
  остаётся в редакторе при ошибке доставки и восстановлении соединения. Возврат
  ввода к прежнему серверному тексту не подтверждает ещё ожидающую отправки правку:
  поздний ответ на промежуточное значение не заменяет этот новый ввод.
- **R-03. Доставка и восстановление:** зависший запрос записи имеет конечный срок
  ожидания; повтор сохраняет исходное намерение. Очередь объединяет только ещё
  не отправленные значения одного поля одной задачи. Кандидатская активность
  сохраняет независимую очередь. После reconnect приватная подписка шага
  восстанавливается до повтора его записей.
- **R-04. Приватное условие и конкуренция:** версия неопубликованного шага берётся
  из последнего подтверждённого сервером состояния. Конфликт версии не считается
  успешным сохранением и не удаляет черновик. Ответ HTTP и актуальное состояние
  SSE могут прийти в любом порядке. Повтор встаёт после уже поставленных действий,
  чтобы новая последовательность не обесценила записи кода или заметок.
  Неотправленные правки Markdown переносятся через внешнее изменение текста;
  одинаковые подтверждения не дублируют ввод. При замене одного и того же фрагмента
  обоими авторами сохраняются оба варианта внутри объединённого текста.
- **R-05. Принадлежность задачи:** ожидающий отправки Markdown хранит UUID исходной
  задачи комнаты. Публикация другого шага не переносит текст в новый шаг: последний
  разрешённый черновик сохраняется в прежнюю задачу и доступен её менеджерам.
  Если исходная задача удалена, сервер сообщает конфликт и не пишет в задачу,
  занявшую тот же индекс. Проверка роли и mandatory/finished/frozen выполняется
  сервером; черновики и их технические метаданные находятся только в памяти
  текущего контекста аккаунта/комнаты, без tokens в UI recovery storage.
  При подтверждённом отзыве manager-роли приватные ожидающие записи, подписки и
  черновики очищаются; позднее приватное состояние игнорируется. Новое назначение
  роли начинает новый приватный контекст и не восстанавливает прежние записи.
- **AC-02:** несколько секунд непрерывного ввода → есть промежуточное сохранение,
  после паузы и перезагрузки текст совпадает полностью.
- **AC-03:** зависший запрос Markdown → запрос отменяется по сроку, восстановление
  соединения сохраняет весь новый текст и подтверждает его без дополнительного ввода.
- **AC-04:** локальный ввод и внешняя правка приватного условия → сохраняются оба
  изменения; позднее подтверждение и реконнект не откатывают локальный черновик.
  HTTP 409 до SSE с новой версией плюс заметка в очереди → автоматически
  сохраняются объединённый Markdown и заметка без нарушения порядка.
- **AC-05:** ввод ожидает отправки, публикуется другой шаг → новый шаг неизменён,
  черновик сохраняется в исходную задачу; удалённый UUID → 409 без чужой записи;
  кандидат с любым UUID → 403.
- **AC-06:** приватная запись ожидает отправки → роль интервьюера отозвана →
  запрос отменён, приватная очередь очищена; после нового назначения интервьюером
  загружается только актуальное состояние, прежний неподтверждённый черновик не
  накладывается и не отправляется заново.
- **AC-07:** промежуточное значение ожидает ответа → пользователь возвращает
  прежний серверный текст до окончания debounce → подтверждение промежуточного
  значения не меняет редактор; последняя правка затем сохраняется полностью.

Проверки Markdown: `e2e-markdown-delivery-reliability.mjs`,
`markdownDraftRecovery.test.ts`, PostgreSQL `MarkdownTaskDeliveryIntegrationTest`.
Текущая правка проверена технически; продуктовая приёмка пользователем остаётся
отдельной. Подтверждения относятся к текущему прогону, история предыдущих layout
прогонов ниже не заменяет эти регрессии.
Причины, результаты и границы проверки:

## Корректировка по продуктовой проверке 2026-09-23

- Видимые переключатели «Фокус» и «Обзор» удалены. Рабочая область адаптируется к размеру окна автоматически; на узкой области вспомогательные вкладки остаются доступными и есть возврат к редактору.
- Переключатель «Только markdown / Вернуть код» расположен на видном месте в верхней панели комнаты. Он меняет основной сценарий редактора для интервьюера и кандидата, а не только боковую панель условия.
- На неопубликованном шаге markdown заменяет основной кодовый редактор локального рабочего пространства; после публикации то же состояние применимо у кандидата.
- Действие называется «Заменить код на Markdown» / «Вернуть редактор кода» и
  визуально выделено. Возврат к списку интервью находится отдельно в шапке,
  называется «Вернуться к списку интервью» и ведёт в пространство текущего
  командного или личного интервью.
- В панели статусов не показываются штатное «Соединение: установлено» и локальный выбор шага. При разрыве связи остаётся предупреждение о восстановлении соединения; опубликованный шаг и состояние кандидата остаются видимыми.

## Корректировка комнаты по скриншотам — 2026-09-24

- «Вернуться к списку интервью» и «Главная» выглядят как отдельные кнопки с видимой границей, состоянием наведения и фокусом.
- «Кандидат и нанимающие» выделено как действие управления с иконкой и явной поверхностью.
- В переключателе markdown и возврата к редактору иконка и подпись имеют постоянный промежуток и общий вертикальный центр.
- Действия участника открываются только кликом или клавиатурой. Постоянная подсказка объясняет, как открыть их; наведение не открывает меню и не сдвигает участника. Меню поддерживает Escape и возврат фокуса.
- Проверки 2026-09-24: room smoke — pass; сценарии hover/click/Enter/Escape у участника прошли в targeted E2E до последующей проверки истории активности. Полный activity harness требует отдельный API на `18080`.

## Повторная проверка во время UI.1 2026-09-23

- Исторический `19/19` относится к предыдущему состоянию, когда Focus/Work/Overview были видимыми режимами. После продуктового решения выше повторный запуск `npm run e2e:room-context-panels` закономерно не проходит проверки, которые ищут эти удалённые кнопки.
- Повторный запуск до обновления этих старых ожиданий: 7 pass / 12 fail. Помимо удалённых переключателей, suite сообщает, что lifecycle log не настроен, и что resize отправляет `manager_workspace_awareness_update`; для последнего нужно отдельно подтвердить актуальный контракт room awareness. Эти проверки не следует «исправлять» возвратом кнопок Focus/Work/Overview.
- В UI.1 адаптер диалога теперь переводит `closeButtonProps` в Ant Design v6 `closable`; проверка экспорта личных заметок и закрытия диалога отдельно прошла. Обычная pointer-target проверка в UI.1 использует проектный default 32 px; 44 px оставлено для coarse pointer по §4.4.
