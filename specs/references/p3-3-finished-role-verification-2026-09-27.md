# P3.3 — проверка прав в завершённом интервью, 2026-09-27

Актуальная спецификация: [P3.3](../features/p3-3-interview-result.md#актуальное-уточнение-пользователя--2026-09-27). Полная блокировка finished из предыдущего UI.2 evidence отменена пользователем.

После завершения owner, назначенный interviewer и назначенный HR продолжают редактирование. Остальные имеют только просмотр, с видимыми подписями «Интервью завершено» и «Только просмотр». Управляющий видит только статус завершения. Изменения не отменяют finished и не меняют первый finishedAt. Глобальный профиль HR не даёт управляющих прав в чужой комнате.

RED воспроизвёл запрет finished-manager языка/кода/заметок, потерю taskless кода, кандидатский неподтверждённый документ, запись клавиатуры после завершения, expired guest write/read authority и зависание403/409 body. Промежуточный полный прогон38/39 обнаружил реальную потерю следующего черновика чата при ACK; два новых unit сценария сначала упали, затем прошли после учёта версии черновика. Проверка queued чата исключает реальные pending подписи «Отправляем…»/«Сохраняем…» и проверяет точный черновик сразу после подтверждения.

Исправлены также ошибки старого тестового harness: скрытая legacy навигация вместо вкладки «Активность», ожидание send-enabled до ACK, сигнал не учитывался в имитации hung request и зарегистрированный владелец входил без своего auth. Проверки исправлены без ослабления UUID/backoff/сохранения/прав.

Изолированный runtime использует собственную временную PostgreSQL schema, backend18081 и frontend5174; cleanup удаляет schema и завершает только эти процессы. Frozen E2E является frontend hydration-контрактом с заменой только lifecycle в реальном SSE; реальные серверные freeze/resume проверены integration тестами. Полный исторический E2E набор не заявляется как пройденный. В taskless Room нет колонок полного Yjs документа: после сброса runtime он восстанавливается из durable code; новый schema/API не добавлен.
