Тесты сначала воспроизвели отсутствующий TEAM каталог/назначение, геометрические и цветовые дефекты. Новые backend сценарии используют реальные PostgreSQL lock waits: изменение metadata revision, снятие членства и HR-функции во время ожидания, взаимные назначения владельцев двух команд. Старый порядок user locks воспроизвёл deadlock; единый порядок actor/targets устранил его. Некорректный UUID, foreign team, не-HR, candidate, отозванная роль и archived не получают новые полномочия; ошибочное создание не оставляет частичной комнаты. Idempotency сохраняет прежний контракт и отклоняет изменённый HR intent.

Независимый security/reliability агент дал PASS после устранения замечаний по актуальности данных после ожидания lock, deadlock и private search. UX агент дал ux-approved. При основном повторе17/17 каталог загружается с уже обновлённого сервера; старые UX скриншоты до применения backend сами по себе не подтверждают загрузку каталога.

Дополнительная проверка прежнего dashboard/HR потока выявила два реальных клиентских дефекта: поиск задач по названию фильтровал внутренний UUID, а promoted guest interviewer прежней PERSONAL комнаты ошибочно направлялся в authenticated `/me` preview перед допустимым room invite. Общий фильтр исправлен; для гостя строгая локальная UUID проверка передаёт назначение существующему room endpoint с прежними credentials/permission checks. Authenticated каталог гостю не открывается, TEAM полномочия не расширяются. Старые проверки адаптированы к новому маршруту создания, прямому Switch профиля и общему UUID, без снятия assertions по ошибкам, черновикам и отзыву прав.

## UX исследование и применение

Дизайнер исследовал официальные [Linear Profile](https://linear.app/docs/profile), [Linear Account Preferences](https://linear.app/docs/account-preferences), [Slack Preferences](https://slack.com/help/articles/201355156-Configure-your-Slack-notifications), [Ant Design Switch](https://ant.design/components/switch/) и [WAI-ARIA Switch Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/switch/). Для текущего интерфейса выбран прямой переключатель одной настройки с явным состоянием сохранения; редактирование имени остаётся отдельным модальным действием. Отдельный UX агент исследовал шапку и независимо проверил реализацию и клавиатурные сценарии.

Backend8080 перезапущен по ранее полученному явному разрешению пользователя, с сохранением конфигурации подключения к базе и ключей. Frontend5173 и PostgreSQL не перезапускались. Проверка `/api/public/health` после применения возвращает `status: ok`.

Изолированный runtime остановлен, его временная schema удалена. Браузерные проверки создают собственные тестовые аккаунты/команды/комнаты; исходная пользовательская комната не изменяется. Feature flags не включаются по умолчанию. Этот отчёт подтверждает перечисленные исправления и регрессии, а не весь исторический E2E набор проекта.
